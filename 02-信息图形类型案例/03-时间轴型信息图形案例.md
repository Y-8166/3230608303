## 0. 类型定位：时间轴的唯一使命

时间轴型信息图形是 [编年型数据逻辑](../01-信息图形数据逻辑/01-编年型信息图形概念定义.md) 的**纯形态产物**。它不是"把事件连成一条线"，而是**用空间的疏密替读者做取舍**。

它的核心矛盾永远是同一个：**事件太多，版面和注意力太少。** 因此时间轴设计的全部技艺，归结为三件事：

1. **刻度怎么定**（等比 / 等距 / 断轴 / 压缩）
2. **疏密怎么排**（哪段密集、哪段留白）
3. **哪几个点被选中**（里程碑的选取即论点）

> **判据**：如果去掉时间轴后，图形仍然成立（事件仍可并列阅读），那它其实是 [编目型](../01-信息图形数据逻辑/03-编目型信息图形概念定义.md) 或 [列表型](02-文字型列表型信息图形案例.md)，不是时间轴。

## 1. 九种形态（形态学）

| # | 形态 | 结构 | 优势 | 代价 | 适用 |
|---|---|---|---|---|---|
| 1 | **水平直轴** | 单条横轴，事件上下交错 | 最符合"前进"心理模型 | 长文案难排 | 企业史、大事记 |
| 2 | **垂直直轴** | 单条纵轴，事件左右交错 | 可容纳长文与配图；适合手机滚动**长图** | 轴向隐喻弱于水平 | 图文长图（最主流） |
| 3 | **蛇形轴**（S / Z 形） | 折返路径填满方形版面 | 版面利用率最高 | 折返点易迷失方向 | 海报、单页概览 |
| 4 | **环形轴** | 极坐标闭合环 | 版面紧凑，能在方形内装 20+ 节点 | **方向直觉最弱**；线性内容易被误读为循环 | 年度回顾、周期 |
| 5 | **螺旋轴** | 由内向外盘旋 | 兼顾"循环"与"推进" | 阅读路径复杂，节点难定位 | 技术演进、文明史 |
| 6 | **阶梯轴** | 台阶式上升 | 强调"跃迁"与代际 | 等距伪装成等比（须声明） | 版本迭代、代际演进 |
| 7 | **泳道轴** | 多条平行轴共享刻度 | 多线程并行对比 | 占空间 | 多项目、多人物、多国 |
| 8 | **分支轴**（时间树） | 主干 + 分叉 | 承认"可能性与现实" | 分叉后时间刻度难统一 | 技术路线、决策复盘 |
| 9 | **甘特/路线图** | 区间条 + 时间刻度 | 精确表达工期与重叠 | 视觉偏"管理工具" | 项目排期、路线图 |

### 1.1 选择决策表

| 条件 | 选 |
|---|---|
| 事件 ≤ 12，文案短 | 水平直轴 |
| 事件 12–25，每条需 20 字以上 or 配图 | **垂直直轴**（首选） |
| 需压进单页海报 | 蛇形轴 |
| 主题是"循环/周期" | 环形轴 |
| 版面紧张但节点多，且愿用版外列表承接文字 | **环形轴 + 四角列表**（见 CASE-T-001） |
| 主题是"累积式演进" | 螺旋轴 |
| 有 3–7 条并行线程 | 泳道轴 |
| 有真实的"分岔与选择" | 分支轴 |
| 关注"持续多久、何时重叠" | 甘特 |

## 2. 刻度：时间轴的第一技术决策

同一批事件，四种刻度会产出四种不同的历史叙事：

| 刻度 | 做法 | 效果 | 风险 |
|---|---|---|---|
| **等比（线性时间）** | 距离 ∝ 真实时长 | 忠实，节奏由历史本身决定 | 密集期挤成一团，稀疏期空荡 |
| **等距（分类轴）** | 每事件等宽 | 可读性最佳，节奏均匀 | **夸大或压缩真实间隔**——必须声明 |
| **对数/开方** | 压缩长跨度 | 适合万年尺度 | 读者难以估算真实间隔 |
| **断轴** | 中断无事件区间 | 节省版面 | 若未显式标注断口 = 欺骗 |

### 2.1 断轴的规范画法
- 断口符号：双斜线 `//` 或波浪断口，**跨整个轴宽**；
- 断口两侧时间标签必须**都标出**（如"1949" … "1978"）；
- 图例或注中说明"此处省略 29 年无重大事件"；
- 断轴每张图**最多 1 处**；2 处以上应改用等距轴。

### 2.2 疏密的三种处理
1. **等距轴 + 密度条带**：主轴保持均匀，事件密度用侧边条带的深浅/长度另表 → **最推荐**，兼顾可读与诚实。
2. **等比轴 + 节点聚合**：密集区把 n 个事件合并为"1990s 系列事件（8 项）"，明细放侧栏。
3. **变形轴**（非线性压缩）：仅在艺术性海报中使用，且必须标注非线性。

## 3. 视觉编码要点

### 3.1 主轴
- 轴粗 : 事件引线粗 = **2–3 : 1**。
- 端点语义：开放箭头 = 仍在延续；实心端点 = 已终止；渐隐 = 时间不可考。
- 起点必须有视觉标记（起点圆点 / 起始年份加重），否则读者不知从何读起。

### 3.2 事件节点
- 形状编码类别（≤ 5 种）：圆=常规事件、方=制度/文件、三角=冲突/危机、菱形=成果/发布、空心=存疑日期。
- 大小编码权重，用**面积**（`r ∝ √v`），直径比 ≤ 1 : 2.5。
- 节点直径通常为轴宽的 **1.5–2.5 倍**，超出即撑破轴线。
- **可用具象物替代几何符号**：当事件本身是具象对象（建筑、器物、人物）时，实景照片的信息量高于任何 ISO 图标（见 CASE-T-001）。

### 3.3 纪元背景
- 色块饱和度极低（亮色主题明度 ≥ 92%），仅作背景分区；
- 相邻纪元之间留 1–2px 缝或明度台阶；
- 纪元名用小型大写/字距加宽，居中于色块。

### 3.4 文字排布
- 垂直轴的左右交错是最稳定的排布（每侧最多 2 行）；
- 第 3 行必须改用**引线拉出**（折线 + 端点），不可继续外扩；
- 标签与节点距离恒定（`12–16px`），一旦不恒定，整条轴就会"跳"。

### 3.5 色彩
- 色相 = 类别（≤ 6 类）；明度 = 时代远近（可选，久远者浅）；
- 强调的是**唯一转折点**，用高饱和点缀色，全图仅 1–2 色相；
- 环形轴的分区色必须**首尾闭合**（最后一个扇区与第一个同族），否则环不成立。

## 5. 案例解析

### CASE-T-001 ｜ 包豪斯环形史（BAUHAUS 1919–1933）

**图版**：第三讲 p.24
**出处**：设计史主题信息图海报（中文／德文双语）
**议题**：以格罗皮乌斯为轴，呈现包豪斯从创立到关闭、再到影响延续的完整轨迹

**① 数据逻辑**
- 时间跨度：约 1906–1967（含建校前史与关闭后影响）
- 事件总数：约 24 个；轴上可见节点：24 个；折叠比 ≈ 1 : 1（未折叠）
- 数据形态：**定点事件**（每年份对应一栋建筑／一个机构节点）
- 非时间量：无（建筑不承载数值）→ 仍属编年型；但辅以地理（城市）与编目（列表）

**② 刻度与布局**
- 形态：**环形轴（第 4 种）**——环上标年份，外侧引线接建筑图
- 刻度类型：**等比时间 + 局部弹性**；1925–1930 段明显压缩，1946–1959 段明显拉伸
- 是否声明：❌ **未声明刻度性质**（这是主要缺陷）
- 疏密处理：靠"年份数字的大小 + 建筑图的疏密"自然形成，未使用密度条带

**③ 视觉编码**
- 主轴：红色大圆（唯一强调色），细红线自环引出至建筑图
- 节点：**年份数字本身充当节点标记**（无独立点符号）
- 纪元：外环弧段分区；内圈为肖像与地图
- 文字：年份（大号红色数字）→ 事件名（黑体）→ 2–3 行说明（小号），三级
- 色彩：**单一强调色红** 贯穿年份、引线、建筑照片描边；黑白照片 + 米色底
- 底图：德国／欧洲地图，仅留国界轮廓与城市点（Weimar / Dessau / Berlin），极淡

**④ 数据/信息架构**
- 层数：标题 → 引言（格罗皮乌斯小传）→ 环 → 建筑图 → 年份 → 说明（六层，偏多）
- 必读节点数：24（**远超本库标准 7**）
- 折叠手法：**双区承载**——环管"何时／何地"，四角列表管"是什么"，以此绕开折叠
- 信息配额：24 节点 / 约 500 字 / 无图例

**⑤ 视觉叙事架构**
- 阅读路径：顺时针（1910 右上 → 底 → 左上 1967）
- 叙事模式：**纪传式**（单对象 = 包豪斯学校）
- 起：1910／1908 建校前史（右上）；转：1933 关闭（环最底部，密度最高）；合：1967 影响延续（左上）
- 唯一高潮：底部 1925–1933 的密集区（建筑最多、年份最挤）

**⑥ 可复用要点**
1. **环形轴是版面压缩手段，不是周期隐喻**：用环装线性史，能在方形版面里容纳 20+ 节点且不留大片空白——但必须配清晰的方向标记（本图未配，见 ⑦）。
2. **用实景照片替代几何符号**：当事件是具象对象（建筑／产品／人物），照片的信息量高一个量级，且自带"时代质感"。
3. **单一强调色贯穿全部结构元素**（年份数字、引线、照片描边），使"时间"成为一眼可辨的色块——这比给每类事件配不同颜色更有效。
4. **地图降为极淡底图**，只提供"在哪"，不与数据争视觉重量。

**⑦ 问题与风险**
- **环形轴用于线性历史，牺牲方向直觉**：环的起点（1910，右上）与终点（1967，左上）几乎相邻，读者极易误读为"循环"。正是 [编年型 C.3](../01-信息图形数据逻辑/01-编年型信息图形概念定义.md) 警告的情形。
- 刻度非等比且**未声明**；1925 年出现两次（不同事件），视觉上却像一个节点。
- 粒度不一致：多数为年份，个别精确到 `1963.5.18`、`1967.5`。
- 四角列表与环上节点**无引线、无编号**对应，读者无法确认某段文字属于哪栋建筑。
- 地图标了 UK、USA、GERMANY，但数据点仅德国境内——英美标注**无对应数据**，属误导。
- 24 个必读节点超载，全图无"主次分层"，读者只能平铺读完。

## 6. 归纳：目前可确立的规则

| # | 规则 | 依据 |
|---|---|---|
| R1 | 轴粗为事件引线粗的 2–3 倍 | T-001 |
| R2 | 等距轴/断轴必须显式声明，断轴每图 ≤ 1 处 | 待验证 |
| R3 | 主轴必读节点 ≤ 7，超出即须折叠或双区承载 | T-001（反例：24 节点无分层） |
| R4 | 节点用面积编码权重，直径比 ≤ 1 : 2.5 | 待验证 |
| R5 | 标签与节点距离恒定，单侧 ≤ 2 行，第 3 行走引线 | T-001 |
| R6 | 纪元色块明度 ≥ 92%（亮色主题），且不得压过数据 | T-001 |
| R7 | 全图唯一高潮，强调色 ≤ 2 色相 | T-001（正例：单红） |
| R8 | 轴起点必须有视觉标记 | T-001（反例：环起点无标记） |
| R9 | 环形轴首尾必须闭合（末扇区与首扇区同族色） | T-001（正例） |
| R10 | **环形轴用于线性内容时，必须在起止点加"起点/终点"标记或箭头**，否则会被读成循环 | T-001（反例） |
| R11 | 具象事件优先用实景物替代几何符号 | T-001 |
| R12 | 结构区（环）与文字区（列表）分区承载时，必须以编号或引线建立一一对应 | T-001（反例） |
| R13 | 底图只标有数据的区域；无数据的国家/城市标注即为误导 | T-001（反例） |
