**暂无已归档案例（0 条）**。该类型在 [00-类型总览](../../00-类型总览.md) 中列为覆盖缺口，规则表条目全部标注「待案例验证」——这是**刻意留空**，不是遗漏。它本身是信息图形与数据可视化的临界样本（一张统计图形直接充当信息图形），找案例时要连「标题主张、注释、强调色、视觉层级」一起举证。

## 新建案例时

1. 在 [案例索引](../../案例索引.md) 取下一个 `CASE-xxxx` 号（只增不减，不复用）；
2. 在本目录下建 `CASE-xxxx-简要名/`，按 [案例分析模板](../../案例分析模板.md) 一次建齐 `README.md`、`分析.md`、`原图.webp`、`原图来源.md`、`数据字典.md`；
3. 判 `dataset_status`：`partial` / `complete` 再加 `基础数据集.csv`（可选 `辅助指标.csv`）；`none` 也必须有字典，写明「为何无值」与「禁止推断清单」；
4. 回写 [00-标签说明](../00-标签说明.md) 的「案例登记表」与规则表，新规则须标注 CASE 编号；
5. 跑 `python scripts/validate_repo.py`，通过后提交。

> **没有原图就不要建目录**：在类型说明里写「暂无原图」，不配假设性插图。
