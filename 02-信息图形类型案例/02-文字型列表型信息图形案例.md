## 0. 类型定位：文字为什么也能是"信息图形"

文字型／列表型信息图形，是**以文字块为信息主载荷**，仅用序号、图标、色块、栅格、留白建立视觉结构，不（主要）依赖统计图形或地图的信息图形。

它常被误认为"排版"而非"信息图形"。但判据很清楚：**当读者能通过版面的空间结构（而非逐字阅读）在 3 秒内掌握信息的组织逻辑时，它就已经是信息图形。**

| | 普通排版 | 文案型信息图形 |
|---|---|---|
| 结构来源 | 段落自然流 | **序号 / 分组 / 图标 / 栅格**显式建立 |
| 阅读方式 | 线性逐句 | **可跳读、可扫读、可定位** |
| 承载信息 | 论述、故事 | **并列事实、步骤、条目** |
| 成功判据 | 读完理解 | **不读完也能抓到骨架** |

它与 [编目型](../01-信息图形数据逻辑/03-编目型信息图形概念定义.md) 的分界：编目型要求**字段对齐**（可比），文字型允许**条目异构**（各条长短、维度不一，只要并列）。因此文字型是"比编目更松"的形态，也是最容易被滥用（沦为"长文加序号"）的形态。

## 1. 五种子型（形态学）

| 子型 | 结构特征 | 隐含逻辑 | 典型场景 |
|---|---|---|---|
| **编号清单**（Ordered List） | 1–N 序号纵向排列 | 弱序（可读作并列，也可读作优先级） | "10 个方法""7 个信号" |
| **对照双栏**（Comparative Pair） | 左/右两列镜像对照 | 二元对立 | "误区 vs 正解""传统 vs 现代" |
| **步骤流**（Process / How-to） | 编号 + 箭头/连线，常配示意小图 | 强序（不可换序） | 教程、操作指引、流程 |
| **问答体**（Q&A） | 问句（重） + 答句（轻）交替 | 对话驱动的认知推进 | FAQ、专家访谈、科普 |
| **卡牌集**（Card Set） | N 张等大卡片网格 | 完全并列 | 要点卡片、系列图文 |

### 1.1 强序与弱序：最重要的一个判断

- **强序**（步骤流）：顺序不可交换。"第 3 步必须在第 2 步之后" → 必须用**箭头 / 连线 / 编号加粗 + 递进色彩**。
- **弱序**（编号清单）：顺序可交换，序号仅作计数与定位 → 序号应做**视觉弱化**（浅灰、小字号、可置于角落）。

> 最常见的错误：把弱序清单画成强序流程（加满箭头），让读者误以为"必须先做 1 才能做 2"，从而增加认知负担。

## 2. 文字型信息图形的通用视觉语法

### 2.1 行宽纪律
单栏每行字符数应控制在 **中文 20–35 字 / 拉丁 45–75 字符**。超出则眼跳回扫失误率上升；低于 15 字则断行过频，破坏语义单元。**这一条没有例外，是文字型的第一硬指标。**

### 2.2 三层字阶
`标题（主张）: 条目名（要点）: 正文（说明）` ≈ **2 : 1.4 : 1**。三层之外不再增层。字重必须参与分层（不能只靠字号），因为纯字号分层在缩略图/手机端会全部塌陷。

### 2.3 序号的三重角色
序号同时承担：**计数（有多少）**、**定位（第几条）**、**节奏（视觉停顿）**。因此序号必须：
- 与条目名**基线对齐**（不可悬空）；
- 视觉尺寸 ≤ 条目名的 1.6 倍（超出即抢戏）；
- 使用同一字体族的数字变体（等宽数字优先，保证纵向对齐）。

### 2.4 图标锚定
每个条目若配图标，图标的作用是**加速定位**而非装饰。规则：
- 图标外接框统一（同尺寸画布、同视觉重量）；
- 图标只表**类别**，不表**程度**（程度交给文字或色块）；
- 图标必须与条目名首字在视觉上"同高"；
- 无图标优于"勉强凑图标"——凑出来的图标会制造虚假分类。

### 2.5 留白即分隔
文字型应尽量用**间距**而非**线框**分隔条目。三种间距层级：
`条目内（行距 1.5–1.7）< 条目间（2–3 倍行距）< 分组间（4–6 倍行距）`。
线框只在条目跨页/跨屏需要强分隔时使用，且线宽 ≤ 1px、透明度 ≤ 25%。

### 2.6 图文比
文字型信息图形的合理图文面积比为 **文字 60–75% : 图形 25–40%**。图形超过 40% 即应向 [混合型](01-混合型信息图形案例.md) 迁移；低于 15% 则只是排版，不构成信息图形。
