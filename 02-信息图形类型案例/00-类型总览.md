## 0. 这张表解决什么问题

第三讲把信息图形切成两层：

- **第一层是"数据架构逻辑"**——只有五类（编年／层级／编目／字母表／地理），由**数据的结构**决定，不可自由选择；
- **第二层是"常用图形种类"**——课件列出十七项，是**表现形式**，同一逻辑可以长出多种形式，不同逻辑也能共用一种形式。

因此本文件夹的组织原则是：**按形式归档（方便找图），按逻辑归类（方便判断该画什么）**。下表同时给出这两个坐标。

## 2. 六类需要说明的边界

### 2.1 「单一图表型」是本门类的临界点

p.31 的 `Single chart` 指的是**一张统计图形直接充当信息图形**（如一张精心设计的桑基图或树图）。

它是**信息图形与数据可视化的分界线**：

- 当图形只求准确传达数据关系 → 数据可视化；
- 当同一张图被加上标题主张、注释、强调色、视觉层级 → 开始成为信息图形。

判别方法见 [混合型 §0](01-混合型-Mixed-Charts/00-标签说明.md#0-类型定位混合型为什么不是第六类)。本库不为它单建规则，因为它的定义就是"不叠加叙事"。

### 2.2 「三维型」不是数据逻辑，是渲染方式

p.38 的 `3D Infographics` 与其余各项不同层级——它描述的是**媒介（立体渲染）**，不是数据组织方式。同一份数据可以是平面时间轴，也可以是立体时间轴。

处理原则：**不将其视为独立逻辑类型**，而在各门类的"编码禁忌"中统一规定——立体只允许用于**高度＝真实数值**的棱柱或层级块，装饰性厚度一律禁止。CASE-0016 的轴测分层生态图就是"层级逻辑 + 轴测渲染"的组合样本。

### 2.3 「解剖型」的双重归属

p.33 的 `Anatomical` 指解剖图／剖层图（如产品爆炸图、器官剖面）。它的逻辑是**层级分解**（整体拆成部件），但部件有**空间位置**，因此常与地理逻辑共用坐标系。

本库归其主导逻辑为**层级型**（分解），参见 [层级型 §B.1](../01-信息图形数据逻辑/02-层级型信息图形概念定义.md)。

### 2.4 两个子型共用名称

p.36 与 p.37 都标为「编年图+编目混合图」。二者是**同一种混合方式的两个实例**，故合并为第 15 项；其深度分析并见 [混合型](01-混合型-Mixed-Charts/00-标签说明.md)（CASE-M-002＝CASE-0015）。

### 2.5 「词云」为什么单独成项

词云在课件里没有独立页，但用户于 2026-11-23 指定加入。它逻辑上属**编目型**（词项—权重集合），形式上属**可视化文本型**的近亲。本库为它单建一文，是因为"字号映射"与"词频可复核性"有独立的技术规范（数据字典、字号映射函数、与艺术排版的区分），塞进 11 号文会淹没。见 [17 词云](17-词云信息图-Word-Cloud/00-标签说明.md)。

### 2.6 「ISOTYPE」已移出本表，独立为顶层 03

ISOTYPE 是 Neurath 的图画统计系统（象形符号重复计数），可用于比较型、单一图表型、混合型等多种形式。

它曾列为第 18 项，2026-11-24 起独立为 [03-ISOTYPE信息图](../03-ISOTYPE信息图/README.md)。理由是**维度不同**：本表其余 17 项回答"长成什么形态"，ISOTYPE 回答"用什么方法把数据变成图形"。一张比较型图可以同时是 ISOTYPE 式；一张贴满象形图标的图，若无"1 图标 = N 单位"的计数结构，也不是 ISOTYPE。

判定门槛见 [三条硬规则](../03-ISOTYPE信息图/00-ISOTYPE概念与方法.md)，画法见 [图符语言与视觉编码](../03-ISOTYPE信息图/01-图符语言与视觉编码.md)。

## 3. 从形式反查逻辑（制图时的实际用法）

拿到需求后，**不要先选形式，先定逻辑**。顺序是：

```
① 数据是什么结构？          → 落到五大逻辑之一（01 文件夹 A 节四问判定）
② 读者要回答什么问题？      → 落在 B.3 决策表
③ 需要多少种逻辑同时在场？  → 1 种 = 纯类型；≥2 种 = 混合型
④ 选形式（本表）            → 同逻辑下挑最省认知成本的那一种
```

**反例**（初学者最常见的路径）：先想"我要做一张时间轴"，再把数据硬塞进去——于是把并列清单画成了时间轴，伪造出并不存在的先后关系。这正是 [四大硬伤](设计准则与评价方法.md#5-四大硬伤与四条铁律) 中"太抽象"的成因。

## 4. 归档规则

新增案例时：

1. 在 [案例索引](案例索引.md) 分配 `CASE-xxxx`（连续编号，不复用）；
2. 在本类型 `案例/` 下建 `CASE-xxxx-名/` 目录，图版命名 `原图.webp`；
3. 在所属类型的 [案例/](01-混合型-Mixed-Charts/案例/) 下建 `CASE-xxxx-名/` 目录，写 `分析.md`，按 [案例分析模板](案例分析模板.md) 的 A–E 填写；
4. 回写本表"已归档案例"列与对应类型文档的规则表——**规则必须带 CASE 编号**，无依据的条目降级为"待验证"。
