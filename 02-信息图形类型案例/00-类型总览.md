## 0. 这张表解决什么问题

第三讲把信息图形切成两层：

- **第一层是"数据架构逻辑"**——只有五类（编年／层级／编目／字母表／地理），由**数据的结构**决定，不可自由选择；
- **第二层是"常用图形种类"**——有十七种，是**表现形式**，同一逻辑可以长出多种形式，不同逻辑也能共用一种形式。

因此本文件夹的组织原则是：**按形式归档（方便找图），按逻辑归类（方便判断该画什么）**。下表同时给出这两个坐标。

## 2. 四类需要说明的边界

### 2.1 「单一图表型」是本门类的临界点

p.31 的 `Single chart` 指的是**一张统计图形直接充当信息图形**（如一张精心设计的桑基图或树图）。

它是**信息图形与数据可视化的分界线**：

- 当图形只求准确传达数据关系 → 数据可视化；
- 当同一张图被加上标题主张、注释、强调色、视觉层级 → 开始成为信息图形。

判别方法见 [混合型案例 §0](01-混合型信息图形案例.md#0-类型定位混合型为什么不是第六类)。本库不为它单建文档，因为它的定义就是"不叠加叙事"。

### 2.2 「三维型」不是数据逻辑，是渲染方式

p.38 的 `3D Infographics` 与其余十六项不同层级——它描述的是**媒介（立体渲染）**，不是数据组织方式。同一份数据可以是平面时间轴，也可以是立体时间轴。

本库的处理：**不将其视为独立类型**，而在各门类的"编码禁忌"中统一规定——立体只允许用于**棱柱图**（高度＝真实数值），装饰性厚度一律禁止。

### 2.3 「解剖型」的双重归属

p.33 的 `Anatomical` 指解剖图／剖层图（如产品爆炸图、器官剖面）。它的逻辑是**层级分解**（整体拆成部件），但部件有**空间位置**，因此常与地理逻辑共用坐标系。

本库归其主导逻辑为**层级型**（分解），参见 [层级型 §B.1](../01-信息图形数据逻辑/02-层级型信息图形概念定义.md)。

### 2.4 两个子型共用名称

p.36 与 p.37 都标为「编年图+编目混合图」。二者是**同一种混合方式的两个实例**，故本表分列两行、但不另设类型。其分析并入 [混合型案例](01-混合型信息图形案例.md)（CASE-M-002）。

## 3. 从形式反查逻辑（制图时的实际用法）

拿到需求后，**不要先选形式，先定逻辑**。顺序是：

```
① 数据是什么结构？          → 落到五大逻辑之一（01 文件夹 A 节四问判定）
② 读者要回答什么问题？      → 落在 B.3 决策表
③ 需要多少种逻辑同时在场？  → 1 种 = 纯类型；≥2 种 = 混合型
④ 选形式（本表）            → 同逻辑下挑最省认知成本的那一种
```

**反例**（初学者最常见的路径）：先想"我要做一张时间轴"，再把数据硬塞进去——于是把并列清单画成了时间轴，伪造出并不存在的先后关系。这正是 [四大硬伤](../03-信息图形方法论/02-设计流程与评估.md) 中"太抽象"的成因。

## 4. 归档规则

新增案例时：

1. 在本表找到子型 → 若已有案例文档，追加到该文档的"案例登记表"；
2. 若尚无案例文档，**先只在本表登记编号**，累积到 3 例再单独建文档（避免产生大量只有一例的空文档）；
3. 编号仍沿用 `CASE-{M|L|T}-NNN`；新建子型时启用新类型码（见 [README §4.1](../README.md#41-编号规则)）。
