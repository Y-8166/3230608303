# 案例写作规范

本文件规定**一条案例怎么写、放在哪**。一张案例图 = 一个 `CASE-xxxx` = 一个目录：

```
<类型文件夹>/案例/CASE-xxxx-名称/
├─ README.md      一屏卡片：类型、页码、数据状态、文件清单
├─ 分析.md        A–E 正文（含 front matter）
├─ 原图.webp      图版（无图则缺省）
├─ 原图来源.md    出处、页码、权利状态
├─ 基础数据集.csv  ← 有数据时
└─ 数据字典.md     ← 有数据时
```

- 总表：[案例索引](案例索引.md)
- 写作模板：[案例分析模板](案例分析模板.md)
- 数据规范：[数据表规范](数据表规范.md)
- 类型总览：[00-类型总览](00-类型总览.md)

> **图片禁令**：图版只能放在各自 `CASE-xxxx/` 目录内，文件名固定 `原图.webp`；`01-信息图形数据逻辑/` 内**永远不放图片**。

---

## 一、证据纪律（不可省略）

1. **观察 / 解释 / 建议三者分开写**。图上看得见的（文字、数值、轴、色彩、位置）算观察；"为什么这样设计"算解释；"下次该怎么做"算建议。
2. **图上读不出的数字不猜**。缩略图分辨率低、字号过小、图例被裁，一律写「待核实」，不填估计值。
3. **不推断作者、动机与传播效果**。课件缩略图不支持这类断言。
4. **一个案例可以有多个合理分类**，但主次只记一次，不因贴了几个标签就算几个样本。
5. **单一案例不得升格为通用原则**。至少两例（其中可含一例反例）才能在类型文档的规则表里立条。
6. **反例必须保留**。与既有规则冲突的样本，标注为反例并写清适用边界，不许删。

## 二、证据等级（每条结论都要能归档到其中一级）

| 等级 | 含义 | 允许写在哪 |
|---|---|---|
| `理论假设` | 来自课件或通行理论，尚无库内案例支持 | 类型文档正文，标注"待验证" |
| `单例观察` | 只有一张图支持 | 案例记录内部，不写入规则表 |
| `跨例模式` | ≥2 例支持 | 类型文档规则表，标 CASE 编号 |
| `有边界的规则` | 有正例也有反例，适用条件明确 | 规则表，正反例都标 |

## 三、课件缩略图的授权状态

`CASE-0001`–`CASE-0016` 的图版是从用户提供的《第三讲·信息图形类型学》课件中提取的**研究缩略图**（WebP，6–45 KB），用于本库内部对照分析。**这不等于取得原作品的独立转载或商业使用授权**；对外再传播、出版、商用前必须核实原作者与出处。记录文件里已标课件页码，便于回溯。

## 四、新增案例的八步

1. **编号**：取 `CASE-xxxx` 连续号（当前用到 0017），不复用、不占位。
2. **建目录**：`<类型文件夹>/案例/CASE-xxxx-名称/`，一次建好（结构见文首）。
3. **存图**：缩略图放该目录 `原图.webp`；无图则写"暂无原图"，**不配假设性插图**。
4. **建表**：按 [数据表规范](数据表规范.md) 判定 `dataset_status`。`complete`、`partial` 建 `基础数据集.csv`；`none` 只建 `数据字典.md`。**先建表，再写 A–E**。
5. **填表**：复制 [案例分析模板](案例分析模板.md) 的 front matter 写进 `分析.md`，逐项填 `case_id / source_page / logic_primary / type_primary / confidence / dataset_status / dataset_path / dataset_dict`。
6. **写 A–E**：A 数据逻辑、B 统计图形与计算、C 视觉编码、D 信息架构、E 视觉叙事。每节都要落到图上具体位置（左上、中央、下栏）；B 节凡有可复算项，写出算式。
7. **回写**：在 [案例索引](案例索引.md) 加一行（含数据表状态列）；在对应 `00-标签说明.md` 的"案例登记表"加一行；若结论足以支持或推翻某条规则，改那条规则并标 CASE 编号。
8. **校验**：`python scripts/validate_repo.py`，再提交。提交信息里写明 CASE 编号。
