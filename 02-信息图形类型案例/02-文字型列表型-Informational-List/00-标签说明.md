## 0. 类型定位：文字为什么也能是"信息图形"

文字型／列表型信息图形，是**以文字块为信息主载荷**，仅用序号、图标、色块、栅格、留白建立视觉结构，不（主要）依赖统计图形或地图的信息图形。

它常被误认为"排版"而非"信息图形"。但判据很清楚：**当读者能通过版面的空间结构（而非逐字阅读）在 3 秒内掌握信息的组织逻辑时，它就已经是信息图形。**

| | 普通排版 | 文字型信息图形 |
|---|---|---|
| 结构来源 | 段落自然流 | **序号 / 分组 / 图标 / 栅格**显式建立 |
| 阅读方式 | 线性逐句 | **可跳读、可扫读、可定位** |
| 承载信息 | 论述、故事 | **并列事实、步骤、条目** |
| 成功判据 | 读完理解 | **不读完也能抓到骨架** |

它与 [编目型](../../01-信息图形数据逻辑/03-编目型信息图形概念定义.md) 的分界：编目型要求**字段对齐**（可比），文字型允许**条目异构**（各条长短、维度不一，只要并列）。因此文字型是"比编目更松"的形态，也是最容易被滥用（沦为"长文加序号"）的形态。

> 第三讲 p.23 用两张图版并置来定义本类，实际上区分了两个面向：**左图为「文字型」**（文本即内容，图形只提供路径与隐喻），**右图为「列表型」**（内容已条目化，靠榜单与卡片建立秩序）。本库按此二分归档。

## 1. 五种子型（形态学）

| 子型 | 结构特征 | 隐含逻辑 | 典型场景 |
|---|---|---|---|
| **编号清单**（Ordered List） | 1–N 序号纵向排列 | 弱序（可读作并列，也可读作优先级） | "10 个方法""7 个信号" |
| **对照双栏**（Comparative Pair） | 左/右两列镜像对照 | 二元对立 | "误区 vs 正解""传统 vs 现代" |
| **步骤流**（Process / How-to） | 编号 + 箭头/连线，常配示意小图 | 强序（不可换序） | 教程、操作指引 |
| **问答体**（Q&A） | 问句（重） + 答句（轻）交替 | 对话驱动的认知推进 | FAQ、专家访谈、科普 |
| **卡牌集**（Card Set） | N 张等大卡片网格 | 完全并列 | 要点卡片、系列图文 |

### 1.1 强序与弱序：最重要的一个判断

- **强序**（步骤流）：顺序不可交换。"第 3 步必须在第 2 步之后" → 必须用**箭头 / 连线 / 编号加粗 + 递进色彩**。
- **弱序**（编号清单）：顺序可交换，序号仅作计数与定位 → 序号应做**视觉弱化**（浅灰、小字号、可置于角落）。

> 最常见的错误：把弱序清单画成强序流程（加满箭头），让读者误以为"必须先做 1 才能做 2"，从而增加认知负担。

## 2. 文字型信息图形的通用视觉语法

### 2.1 行宽纪律
单栏每行字符数应控制在 **中文 20–35 字 / 拉丁 45–75 字符**。超出则眼跳回扫失误率上升；低于 15 字则断行过频，破坏语义单元。**这一条没有例外，是文字型的第一硬指标。**

### 2.2 三层字阶
`标题（主张）: 条目名（要点）: 正文（说明）` ≈ **2 : 1.4 : 1**。三层之外不再增层。字重必须参与分层（不能只靠字号），因为纯字号分层在缩略图/手机端会全部塌陷。

### 2.3 序号的三重角色
序号同时承担：**计数（有多少）**、**定位（第几条）**、**节奏（视觉停顿）**。因此序号必须：
- 与条目名**基线对齐**（不可悬空）；
- 视觉尺寸 ≤ 条目名的 1.6 倍（超出即抢戏）；
- 使用同一字体族的数字变体（等宽数字优先，保证纵向对齐）。

### 2.4 图标锚定
每个条目若配图标，图标的作用是**加速定位**而非装饰。规则：
- 图标外接框统一（同尺寸画布、同视觉重量）；
- 图标只表**类别**，不表**程度**（程度交给文字或色块）；
- 图标必须与条目名首字在视觉上"同高"；
- 无图标优于"勉强凑图标"——凑出来的图标会制造虚假分类。

### 2.5 留白即分隔
文字型应尽量用**间距**而非**线框**分隔条目。三种间距层级：
`条目内（行距 1.5–1.7）< 条目间（2–3 倍行距）< 分组间（4–6 倍行距）`。
线框只在条目跨页/跨屏需要强分隔时使用，且线宽 ≤ 1px、透明度 ≤ 25%。

### 2.6 图文比
文字型信息图形的合理图文面积比为 **文字 60–75% : 图形 25–40%**。图形超过 40% 即应向 [混合型](../01-混合型-Mixed-Charts/00-标签说明.md) 迁移；低于 15% 则只是排版，不构成信息图形。

## 4. 案例解析

### CASE-L-001 ｜ 纽约时报评论版「Too Big to Fail, or to Survive」

**图版**：第三讲 p.23 左
**出处**：*The New York Times* Sunday Opinion，2009 年 8 月 23 日
**议题**：以"大而不能倒"为主题，用一条贯穿版面的河流串联多篇独立评论

**① 文字逻辑拆解**
- 子型：**文字型**（非编号清单，属"文本 + 结构路径"的特殊形态）
- 强序 / 弱序：**弱序**——四五篇文章彼此并列，无先后关系
- 条目数：4 篇主文 + 若干短评栏
- 条目同构性：**不同构**（各文主题、长度、体例均不同）→ 这是它不能归入编目型的原因

**② 结构建立手段**
- 序号：无
- 分组：靠**河流的走向**分组——河左岸、河右岸、河尽头
- 图标：无
- 色块：无（纯黑白）
- 线框：一条极细的正文栏分隔线；无卡片框

**③ 视觉编码**
- 字阶：报头／主标题／引题／正文／图注，**五级**（报纸体例的特殊性，超出 2.2 的三层上限，靠**字体族**而非字号区分）
- 行宽：英文约 30–40 字符／行，偏窄；这是报纸多栏体的必然结果
- 色彩：纯黑白 + 灰度
- 图文面积比：≈ **文字 88 : 图 12**
- 结构符号：**一条宽度不断变化的白色河流**——它同时是分割线、引导线与视觉隐喻

**④ 数据/信息架构**
- 层数：报头 → 主标题 → 河流（结构层）→ 左右文本栏 → 插入引语框
- 折叠手法：长文不折叠，靠**版面分区**（河把版切成若干块，每块容纳一文）
- 信息配额：文字量极大（约 2500 字），全篇仅 1 个图形元素

**⑤ 视觉叙事架构**
- 阅读路径：**沿河自上而下**（河流即阅读方向箭头）
- 叙事模式：分布式（多篇并置，无统一主角）
- 起：顶部大标题 + 首字母下沉（Drop Cap）；转：中段引语框打断文本流；合：河尽头的小房子插图（视觉终点）
- 唯一高潮：中段那条引语框"Bail out Fannie Mae and Freddie Mac…"

**⑥ 可复用要点**
1. **"一条有形状的空白"就能组织整版文字**：不靠线框、不靠色块，靠负空间形成路径——这是文字型最经济的结构手段。
2. **结构线宽度的变化承担节奏**：宽处文字退让、窄处文字逼近，形成呼吸，替代了小标题的停顿功能。
3. **图形不必承载数据，可以只承载隐喻**：在文字型里这是合法且高效的（河＝"大而不能倒"的体量隐喻），但代价是需要读者自行联想。

**⑦ 问题与风险**
- 河流与"大而不能倒"的关联**无图注说明**，隐喻成本高，读者可能完全读不出。
- 河流切断了文本流，却**没有箭头指示顺序**，上下块衔接处易断。
- **临界样本警告**：删掉河流，全文仍可读——这说明图形在此是**修辞**而非**结构**。对照时间轴型"删轴即崩"的判据（见 [时间轴案例 §0](../03-时间轴型-Timeline/00-标签说明.md)），本图处于信息图形与版式设计的边界上。本库收录它，正是为了标出这条边界。

### CASE-L-002 ｜ 披头士《LOS CUATRO GENIOS》

**图版**：第三讲 p.23 右
**出处**：西班牙语信息图海报，主题为披头士乐队四人
**议题**：让读者相信"这四个人共同构成了流行音乐史的顶点"

**① 文字逻辑拆解**
- 子型：**列表型**（双榜单 + 四人物卡片 + 成员演变）
- 强序 / 弱序：整体**弱序**；唯"成员演变"一区为**强序**（用箭头串联 1958→1970）
- 条目数：榜单 30 + 20 条；人物档案 4 条；演变 6 段
- 条目同构性：四人物档案**同构**（名 / 乐器图标 / 两段正文）→ 已接近编目型

**② 结构建立手段**
- 序号：榜单有排名数字（1–30、1–20），右对齐
- 分组：纵向三段（上：导语 + 饼图 + 地图；中：人物 + 潜艇剖面 + 演变；下：双榜）
- 图标：乐器线性图标（吉他／贝斯／鼓）表角色
- 色块：无卡片底板，靠留白与细线分隔
- 线框：榜单表格用极细横线

**③ 视觉编码**
- 字阶：名（粗、大写、字距加宽）／正文（小号衬线）／榜单（无衬线、右对齐数字），三层
- 行宽：正文约 45–55 字符，合规
- 色彩：米黄做旧底 + 黑 + 少量红；两榜单分别用橙红渐变条与青绿单色条
- 图文面积比：≈ **文字 55 : 图 45**（已接近混合型的阈值）
- **单元格内嵌条形**：榜单每行末尾一条水平条，长度＝票数／排名强度

**④ 数据/信息架构**
- 层数：主标题 → 导语 → 三段内容区 → 条目 → 单元格内条形（五层）
- 视觉锚：**中央合成人像**（四张脸叠合）——唯一非数据元素，却占据视觉中心
- 折叠手法：榜单只给前 30／前 20，其余不列；人物档案每段限 4–5 行
- 信息配额：条目 60+，文字约 900 字，图例 0

**⑤ 视觉叙事架构**
- 阅读路径：上（兴趣入口：饼图 + 人像）→ 中（个体认知：四档案）→ 下（数据强度：双榜）
- 叙事模式：编目式（均质铺开，制造"全景感"）
- 起：标题 + 合成人像；转：中部的成员演变区（唯一强序，节奏突变）；合：两个榜单给出"历史地位"的结论
- 唯一高潮：中央合成人像

**⑥ 可复用要点**
1. **单元格内嵌条形**是让表格具备图形说服力的最低成本手法：不额外占版面即获得排序直觉。
2. **用非数据元素作视觉锚**（合成人像）是列表型罕见的破均质手段——数据环绕四周，注意力被锚吸住后再向四周释放。
3. **两榜单用不同色系**，明确提示"这是两组独立事实"，避免读者误读为同一排名的延续。
4. **局部强序**（成员演变用箭头）与周围弱序形成对比，成为整版的节奏变化点。

**⑦ 问题与风险**
- 榜单条形**未标刻度**，条长只能相对比较，不可读绝对值。
- 左榜为**渐变彩色条**、右榜为**单色条**——同一张图两套编码规则，不一致。
- 饼图四片占比与图例数字是否自洽**无法核实**（图例字号过小），且未给总数。
- 黄色潜水艇剖面图的标注字极小，且与"乐队史"主题关联薄弱，**接近 chartjunk**（为好看而加）。
- 背景做旧纹理降低了正文对比度，违反可读性优先。
- 严格说它已属**混合型**（含饼图、地图、剖面图），本库按课程 p.23 的归类放在此处，并在 [混合型案例](../01-混合型-Mixed-Charts/00-标签说明.md) 中交叉引用。

## 5. 归纳：目前可确立的规则

| # | 规则 | 依据 |
|---|---|---|
| R1 | 单栏行宽中文 20–35 字、拉丁 45–75 字符，超出必须分栏 | L-001、L-002 |
| R2 | 弱序清单不得使用箭头/连线（避免伪造强序）；强序必须用箭头 | L-002（演变区正例） |
| R3 | 字阶最多三层，且必须同时改字重；报载体例可放宽至五级，但须靠字体族区分 | L-002（正例）、L-001（特例） |
| R4 | 图标只表类别不表程度；凑不齐则不用 | L-002 |
| R5 | 用间距分隔条目，线框仅作兜底 | L-002 |
| R6 | 图文面积比 60–75 : 25–40，越界即应换类型 | L-001（88:12，偏文字）、L-002（55:45，已近混合型） |
| R7 | 单元格内嵌条形必须标刻度，否则只能作相对比较 | L-002（反例） |
| R8 | 同一图内不得混用两套条形编码规则（渐变 vs 单色） | L-002（反例） |
| R9 | 判断某图是否真为"文字型"：删掉图形后若无损可读，则图形是修辞而非结构 | L-001 |
