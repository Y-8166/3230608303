## 0. 一句话定义

**编目型信息图形，是把一组彼此并列、无时序、无隶属关系的对象，按统一的字段模板逐个登记并排布成可扫读、可比对的版面，从而回答"有哪些、各是什么、差在哪"的信息图形。**

三个否定定语是它的身份证明：**无时序**（不是编年）、**无父子**（不是层级）、**无位置约束**（不是地理）。它唯一的组织力量来自**字段一致性 + 排布秩序**。

**课程未给出本门的三段式定义**——p.10 仅有标题页（`3-3：编目型信息图形 / Cataloged Infographics`），p.11–13 为案例图版。以下三行据本门类数据特征补拟，供后续与课程讲义对齐时校验：

|---|---|---|
| **数据逻辑** | 并列、无序、同构 → 实体—属性矩阵 | 无时序、无父子、无位置 |
| **数据维度** | 每项含多个字段，**字段集合全项一致** | 这是与列表型的唯一边界 |
| **视觉编码** | 网格为主，靠对齐与重复建立秩序 | 变化量极少，秩序感即说服力 |

### 术语核对

课程中本门出现了**两个不同的英文名**，需留意：

## A 基本的数据逻辑

### A.1 本质数据结构

编目型的本质是**实体—属性矩阵（Entity–Attribute Matrix）**：行是对象，列是字段，单元格是值。要求**每行结构完全相同**——这就是"编目"与"清单"的分水岭。

```
items[i] = { id, name, attrs{ k1: v1, k2: v2, ... kM: vM }, visual? }
```

| 要素 | 语义 | 硬约束 |
|---|---|---|
| `id` | 对象唯一标识 | 必备，用于交叉引用 |
| `name` | 名称 | 必备，是读者的入口键 |
| `attrs` | 属性字典 | **键集合必须对所有对象一致**（缺值填"—"，不可整列缺席） |
| `visual` | 图形载体（图鉴图、图标、照片、象形单位） | 可选，但一旦启用须全部对象都有 |

三种合法的编目形态：

| 形态 | 对象间关系 | 排布逻辑 | 典型产物 |
|---|---|---|---|
| **名册型**（Roster） | 完全并列，仅共享字段 | 网格 / 列表 | 团队介绍、器材清单 |
| **图鉴型**（Catalog） | 并列，且每项配图形 | 卡片网格（图 + 名 + 字段） | 物种图鉴、产品图录 |
| **比照型**（Comparison） | 并列，且字段值**需要横向比较** | 表格 / 并列条形 / 点阵 | 参数对比表、选型表 |

> **判定核心**：编目型的价值不在"单个对象"，而在**同一字段跨对象的对比**。若读者只关心某几个对象各自的完整故事，那应写成文章或卡片图文，不是编目。

### A.2 四问判定检验

1. **并列检验**：对象之间是否**没有**时间先后、没有上下级、没有空间位置关系？
   → 是：编目型成立。
   → 有一项不成立：优先归入 [编年](01-编年型信息图形概念定义.md) / [层级](02-层级型信息图形概念定义.md) / [地理](05-地理图形信息图形概念定义.md)。
2. **同构检验**：能否为所有对象抽出**同一套字段**？
   → 能：编目型。
   → 不能（各对象描述维度差异极大）：降级为**列表型**（[见 02 文件夹](../02-信息图形类型案例/02-文字型列表型-Informational-List/00-标签说明.md)），只需序号与名称，不追求字段对齐。
3. **规模检验**：对象数量 `n` 是多少？
   → `n ≤ 6`：无需编目，直接并列卡片或正文即可。
   → `6 < n ≤ 40`：编目型最佳区间。
   → `n > 40`：必须引入**索引结构**（分组 + 检索），此时向 [字母表型](04-字母表型信息图形概念定义.md) 过渡。
4. **比较检验**：是否存在至少 1 个**需要横向比较的数值字段**？
   → 有：升级为比照型，字段用条形/点阵/象形编码，而不只是文字。
   → 无：名册型或图鉴型即可，纯文字字段。

### A.3 与相邻门类的边界

| 易混对象 | 分界点 |
|---|---|
| **列表型（文字型）** | 列表型只有"序号 + 短句"，字段不对齐；编目型**字段必须对齐**，对齐即产生比较能力。 |
| **层级型** | 编目对象**互不包含**。一旦分组具有"整体—部分"的可加语义，即为层级。注意：编目允许**平级分组**（如按材质分组的器材表），但组与组之间不可加。 |
| **字母表型** | 编目的排序依据是**语义/重要性/规格**；字母表型的排序依据是**名称字符串**。规模大到需要检索时，二者合流。 |
| **表格（数据表）** | 数据表是分析工具（可排序、可计算），编目型是**阅读产品**（已排序、已取舍、带视觉层级）。编目型通常只保留 3–6 个字段，而数据表可以有 50 列。 |

### A.4 常见数据缺陷与处置

| 缺陷 | 处置 |
|---|---|
| 字段不齐（A 项有 5 个字段，B 项只有 2 个） | 要么补全，要么**整列删除**；禁止留出参差的空白，那会破坏网格秩序 |
| 量纲混杂（长度用 cm、重量用 kg、价格用元混排在一个"规格"列） | 拆列，或统一为单位后在单元格内标单位（"1.2 kg"） |
| 数值精度不一（1.5 / 1.53 / 1.532） | 统一有效位数，遵循"最粗的那一项" |
| 对象数量 > 40 且无分组 | 强制分组（3–6 组），否则读者无法定位 |
| 缺值多 | 用"未提供"而非空白；空白会被误读为"零" |
| 名称长度差异极端（2 字 vs 30 字） | 设定名称列最大宽度 + 两行截断规则，统一处理 |

## B 借用的统计图形与计算方式

编目型借用的统计图形最少，因为它**以"排布"代替"绘图"**。但当需要横向比较时，它会借用以下几类：

### B.1 图形谱系

| 借用图形 | 编码通道 | 适用字段 | 说明 |
|---|---|---|---|
| **表格（Table）** | 位置 + 对齐 | 全部字段 | 编目型的默认骨架，最中性 |
| **卡片网格（Card Grid）** | 位置 + 面积 | 名 + 图 + 3–5 字段 | 图鉴型主力 |
| **象形单位阵列**（Unit / Waffle Chart） | 符号计数 | 一个数量字段 | "1 图标 = 1 单位"，直观但占面积 |
| **并列条形**（Bar in cell） | 长度 | 一个数值字段 | 单元格内嵌微型条形，实现"表 + 图" |
| **点阵 / 斜率图**（Dot plot / Slopegraph） | 位置 | 多对象单指标排序 | 替代条形，墨水比更高 |
| **图标矩阵**（Icon Array） | 网格 + 图标差异 | 类别字段 | 用图标区分品类，替代文字标签 |
| **雷达图**（Radar） | 角度 + 半径 | 多指标同量纲 | ⚠ 仅当指标 ≥ 4 且量纲统一；否则误读严重 |

### B.2 计算方式

1. **排序**：编目型**必须排序**。三种依据：
   - 按主指标降序（默认，便于比较）；
   - 按语义分组（按用途/材质）；
   - 按名称（仅在无主指标时，此时向字母表型滑动）。
2. **归一化**：跨对象比较时，`score = (v − min)/(max − min)`，把不同量纲压到 0–1 以适应单元格内条形宽度。
3. **分组计数**：`n_group`，用于分组标题后附"（12 项）"。
4. **排名（rank）**：`rank = 1 + count(v_j > v_i)`，可与分组结合（"组内第 2"）。
5. **分档（binning）**：把连续值切成 3–5 档（低/中/高），用于图标或色块表达，牺牲精度换扫读速度。
6. **列宽预算**：`w_k ∝ max_len(values_k)`，但需设上限，避免某一列吞掉 60% 版面。

### B.3 选择决策表

| 读者问题 | 选用 | 理由 |
|---|---|---|
| 有哪些？各自什么规格？ | 表格 / 卡片网格 | 字段完整 |
| 哪几个最强/最贵/最大？ | 排序 + 单元格内条形 | 比较直觉 |
| 有哪些类别，各多少？ | 图标矩阵 / 象形阵列 | 计数可视 |
| 多指标谁更均衡？ | 点阵（并列）优先于雷达 | 雷达易误读 |
| 选型决策（取舍）？ | 比照表 + 高亮最优格 | 对齐即比较 |

## C 视觉编码

编目型的视觉编码目标不是"表达数据"，而是**建立秩序感**——读者必须相信"这张图里的每一项都被同等严肃地对待过"。因此编码的重点是**重复与对齐**，而非变化。

### C.1 编码总表

| 视觉变量 | 在编目型中承担什么 | 强度 |
|---|---|---|
| **位置（网格）** | 唯一的组织力量：列宽、行高、间距 | ★★★★★（骨架） |
| **面** | 卡片底板、分组色带、隔行底纹 | ★★★ |
| **线** | 表格分隔线、卡片描边 | ★★★（越少越好） |
| **点** | 单元格内点阵、评级圆点 | ★★ |
| **符号** | 对象图形、品类图标、象形单位 | ★★★★（识别核心） |
| **色彩** | 分组、状态标记、优劣高亮 | ★★★（克制） |
| **体** | 极少；仅"图鉴实物"允许轻微投影 | ★（禁装饰立体） |
| **文字** | 名称、字段值、单位、序号 | ★★★★★（主载荷） |

### C.2 逐项要点

**位置／网格（骨架）**
- **列宽必须统一**：同类字段在所有行中占同一宽度。这是编目型的第一纪律。
- **行高阶梯**：主行（带图）高，次行（纯文字）矮，比值约 1.6 : 1；同级别行高严格一致。
- **栅格系统**：采用 12 栏或 8px 基线网格；所有间距取 8 的倍数（8/16/24/32），版面的"秩序感"主要来自这个数学一致性。
- **留白比例**：卡片内边距占卡片面积 12–18%；低于 8% 会拥挤，高于 25% 会散架。

**面**
- 卡片底板与背景的明度差控制在 **3–6%**，靠极轻的色差而非重描边区分卡片。
- 分组色带用**低饱和长条**置于组标题上方，长度 = 该组内容宽度（不是整版宽），形成"句读"。
- 隔行底纹（zebra）仅在行数 > 12 且列数 > 4 时启用，透明度 ≤ 4%。

**线**
- **表格线越少越好**：理想状态是"零竖线 + 三条横线"（表头上下 + 表尾）。竖线用对齐替代。
- 若必须保留分隔线，线宽 0.5–1px，颜色为文字色的 15–25% 透明度。
- 卡片描边 1px，浅灰；描边与底板不要同时使用（会显脏）。

**符号（识别核心）**
- 图鉴型对象图必须**同视角、同背景、同缩放逻辑**（如统一正视图、统一去背）。视角不一致会让整版失去"图鉴"的可信度。
- 品类图标统一线宽、统一视觉尺寸（不是统一画布尺寸）；图标外接圆直径差 ≤ 10%。
- 象形单位（unit chart）必须标注基数，且用**截断**表现半单位，禁止缩放单个符号。

**色彩**
- 色彩在编目型中只做三件事：**分组**（色相）、**状态**（红=告警/缺货，绿=正常——注意行业惯例）、**高亮**（唯一 accent）。
- 分组数量 ≤ 6；超出改用"图标 + 文字"分组。
- 单元格内数值条形统一单色（通常中性蓝或品牌主色），**不要按大小自动渐变**，否则读者会以为是第三个维度。
- 全局 accent 色 ≤ 1 个，仅用于"推荐项/最优值"。

**文字**
- 字段顺序恒定：`名称 → 图形 → 主指标 → 次要指标 → 备注`。顺序一旦确定，全篇不换。
- 数值列**右对齐或小数点对齐**；文本列左对齐；单位写在表头而非每格（"重量 (kg)"优于每格写 kg）。
- 字重三级：对象名（Medium）／字段值（Regular）／单位与备注（Light + 降透明度）。
- 行内文字不超过 2 行；第 3 行必须改为"…"并在注中展开。

### C.3 编码禁忌

- ❌ 行高不齐、列宽不齐（秩序感一破，编目型的价值即消失）
- ❌ 竖线满格（"Excel 味"，会把阅读产品降级为数据表）
- ❌ 每个卡片用不同颜色（颜色失去分组语义，变成噪声）
- ❌ 对象图片视角/光照不一致
- ❌ 单元格内条形按值渐变上色（二维编码冲突）
- ❌ 字段缺失留空（应填"—"或"未提供"）
- ❌ 对象超过 40 个仍不分区分组

## D 数据／信息架构

### D.1 层结构

```
┌─ 叙事层   主标题（编目范围与判断）/ 副标题（口径）
├─ 索引层   分组标题 + 组内计数 + （可选）页码/锚点
├─ 条目层   卡片或表格行：名 → 图 → 字段
├─ 字段层   表头 / 字段标签 / 单位
└─ 框架层   网格、栏线、留白节奏
```

### D.2 四种架构模式

| 模式 | 结构 | 适用 | 容量 |
|---|---|---|---|
| **网格矩阵** | m 列 × n 行卡片 | 图鉴、产品录 | 6–24 项 |
| **表格式** | 行 × 列严格对齐 | 比照、选型 | 10–30 行 |
| **分组纵列** | 纵向分组 + 组内列表 | 名册、目录 | 3–6 组 |
| **双栏对照** | 左右镜像（A 组 vs B 组） | 二选一决策 | 每侧 ≤ 8 项 |

### D.3 折叠策略

1. **分组折叠**：`n > 20` 时按 3–6 组切分，组标题承担"导航"职能。
2. **字段折叠**：字段数 > 6 时，保留 4 个核心字段在版面上，其余移入"详细信息"或脚注。
3. **分层呈现**：首屏给"名称 + 图 + 1 个主指标"，次级页/展开区给完整字段（数字端的"卡片 + 详情页"即此结构）。

### D.4 信息层级配额

- 对象数：**6–40**
- 每对象字段：**3–6**
- 分组数：**3–6**
- 图标/图片：**每个对象 1 个**
- 文字总量：**120–400 字**（编目型的文字密度天然高于其他门类）

## E 视觉叙事架构

### E.1 阅读路径

| 模式 | 路径 | 心理模型 |
|---|---|---|
| 网格矩阵 | 左上 → 右下（Z 字扫描） | 翻阅图鉴 |
| 表格式 | 自上而下逐行 + 横向比字段 | 查表 |
| 分组纵列 | 沿分组标题跳跃 | 目录检索 |

编目型的阅读是**非线性的**——读者会"跳读"。因此必须提供**双重定位线索**：位置（第几组第几个）+ 视觉（图片/图标）。**没有图片的编目型，跳读效率会下降一半以上。**

### E.2 四种叙事模式

| 模式 | 结构 | 传达的判断 | 场景 |
|---|---|---|---|
| **图鉴式** | 同构卡片均质铺开 | "这是一个完整的谱系" | 物种、器物、车型、字体 |
| **排行榜式** | 单一主指标降序 + 排名 | "谁更强" | 榜单、评测 |
| **选型式** | 字段对齐 + 最优格高亮 | "在这些约束下该选谁" | 参数对比、采购 |
| **名册式** | 均质网格，弱排序 | "规模与阵容" | 团队、成员、装备 |

### E.3 叙事节奏

编目型天然缺乏戏剧性，节奏靠在**均质中制造一处例外**：

- **起**：组标题 / 表头，建立"阅读契约"（我按什么顺序排、字段是什么）。
- **转**：全篇**唯一的高亮项**（推荐、最优、新加入），用 accent 色 + 略大的底板或一个角标。
- **合**：结尾一句**归纳判断**（"共 24 项，其中 8 项满足 X 条件"），而非感叹。

> **均质的价值**：编目型的说服力来自"我没有偏袒任何一项"。因此例外只能有**一处**；两处以上，读者会怀疑排序被人为操纵。

### E.4 图文分工

| 通道 | 只负责 | 禁止 |
|---|---|---|
| 主标题 | 编目范围 + 判断（"24 款机型，只有 3 款支持双向充电"） | "产品一览" |
| 组标题 | 分组依据 + 项数 | 描述性长句 |
| 字段值 | 精确值 + 单位（单位在表头） | 主观评价词 |
| 备注 | 例外说明、口径 | 重复字段值 |

---

## F 设计检查清单

- [ ] 对象之间是否真的并列（无时序、无父子、无位置）？
- [ ] 所有对象的字段集合是否完全一致？
- [ ] 是否已排序？排序依据是否标注？
- [ ] 列宽、行高是否严格统一？
- [ ] 竖线是否已减到最少（≤ 3 条横线为佳）？
- [ ] 对象图是否同视角、同背景、同视觉尺寸？
- [ ] 分组是否 ≤ 6 组，每组 ≤ 12 项？
- [ ] 单元格内条形是否单色（未按值渐变）？
- [ ] 缺值是否填"—/未提供"，无空白格？
- [ ] 全篇是否只有一处高亮？
- [ ] 数值是否右对齐/小数点对齐，单位是否在表头？
- [ ] 主标题是否给出范围与判断？
