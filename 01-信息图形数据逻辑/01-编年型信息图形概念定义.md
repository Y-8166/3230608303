## 0. 一句话定义

**编年型信息图形，是以单一、单调、不可逆（或可循环闭合）的时间轴为唯一组织骨架，将离散事件、持续区间与时代背景沿轴定位，从而回答"何时发生、先后如何、何者因果"的信息图形。**

它的核心不是"展示时间"，而是**用时间给信息排序并赋予因果读感**。没有因果或先后诉求的时间数据，只是一张折线图，不构成编年型信息图形。

## 0.1 课程原始定义（第三讲 p.3）

本门的权威表述出自《第三讲·信息图形类型学》3-1 节，以三个维度概括：

| 维度 | 课程原文 | 本库对应章节 |
|---|---|---|
| **数据逻辑** | 单向、不可逆、顺序排列 | A 基本的数据逻辑 |
| **数据维度** | 单维为主，较少延伸数据 | A.1 数据形态 / B.3 决策表 |
| **视觉编码** | 线性为主，具高度可变性 | C 视觉编码 |

**逐条释义**：

- **「单向」**指时间只有一个流向，不能折返；**「不可逆」**指因果不可倒置；**「顺序排列」**指记录必须按 `t` 排序才有意义。三者共同构成编年型的**合法性条件**——缺任一条，就不该画成时间轴。
- **「单维为主，较少延伸数据」**是本门类最容易被违反的约束。课程明确指出编年型的典型形态是"时间 × 一个对象"的一维推进；一旦叠加第二个量纲（销量、温度、兵力），图形即升级为**混合型**（见 [混合型案例](../02-信息图形类型案例/01-混合型信息图形-Mixed-Charts.md)）。这条与本文 A.2 第 4 问（量纲检验）完全一致。
- **「线性为主，具高度可变性」**点出编年型的核心张力：**骨架是线，但这条线的形态几乎可以任意改造**——直轴、蛇形、环形、螺旋、分支皆可，只要保持单向与顺序。这正是本门类形态最丰富（见 [时间轴案例](../02-信息图形类型案例/03-时间轴型信息图形-Timeline.md) 九种形态）的原因。

> **源出**：《第三讲·信息图形类型学》3-1 编年型信息图形（Chronological Infographics），p.3。

## A 基本的数据逻辑

### A.1 本质数据结构

编年型的本质数据结构不是二维表，而是**带时间坐标的有序元组序列**。任一记录都必须能写成：

```
(t, entity, payload, span?)
```

| 字段 | 含义 | 是否必需 |
|---|---|---|
| `t` | 时间戳（点时刻）或时间区间 `[t_start, t_end]` | 必需，且必须**可比较、可排序** |
| `entity` | 该事件归属的对象（人、公司、产品、国家） | 必需，单对象时可隐式省略 |
| `payload` | 事件语义（标签 + 类别 + 可选的量值） | 必需 |
| `span` | 持续时长 / 影响半径 | 区分"点事件"与"状态区间" |

因此编年型只接受四种数据形态，这四种形态决定了后面所有的图形选择：

| 形态 | 数据签名 | 语义 | 典型产物 |
|---|---|---|---|
| **定点事件**（Point Event） | `(t, label, category)` | 某一刻发生了某事 | 里程碑、大事记 |
| **区间状态**（Interval / State） | `(t_start, t_end, label, lane)` | 某状态持续了一段时间 | 任期、版本周期、工期 |
| **时间序列**（Series） | `(t, value)` 等间隔或不等间隔 | 量值随时间变化 | 折线、面积、阶梯 |
| **纪元背景**（Era） | `(t_start, t_end, name)` | 一段被命名的时代，用于给事件分组 | 朝代、技术代际 |

> **关键判据**：编年型的"时间"是**索引**，不是**度量**。时间轴用来排序定位；时间若被当作被测量的因变量（例如"反应时间分布"），那属于统计图形范畴，不是编年型。

### A.2 四问判定检验

一个数据集是否应当走编年型，依次回答：

1. **去时间检验**：删掉时间字段后，图形是否立刻崩塌、信息损失过半？
   → 是：时间承担骨架，进入编年型。
   → 否：时间只是其中一个属性，应走编目型（见 [03 编目型](03-编目型信息图形概念定义.md)）。
2. **单调性检验**：时间是否单调递增且可无歧义展开（线性轴 / 循环轴 / 分支轴）？
   → 出现"时间倒流""并行宇宙"式多线程，需转入**泳道并行**或**分支时间轴**结构，而非放弃编年型。
3. **点/段检验**：记录是"一刻"还是"一段"？
   → 混用必须在视觉上区分（点符号 vs 条带），否则读者会把工期读成事件。
4. **量纲检验**：除时间外是否还有需要编码的数值量？
   → 有，且量值重要：编年型将升级为**混合型**（时间轴 + 统计图形叠加），见 [混合型案例](../02-信息图形类型案例/01-混合型信息图形-Mixed-Charts.md)。

四问全过 = 纯编年型（适合时间轴型信息图）；第 4 问为"是" = 编年型骨架的混合图形。

### A.3 与相邻门类的边界

| 易混对象 | 分界点 |
|---|---|
| **统计折线图** | 折线图回答"变化了多少"（量的趋势），编年型回答"何时、先后、因果"。折线图的时间轴是**均质刻度**；编年型的时间轴是**可伸缩的叙事载体**，允许等距压缩与断轴。 |
| **层级型** | 层级型的主轴是**包含关系**；若时间被用来表达"代际传承"（父→子→孙），主逻辑仍是层级，时间只是排序副键。 |
| **地理图形** | 主轴换成空间（位置/路径/邻接）即为地理型。二者叠合时（如行军路线图）属混合型。 |
| **流程/步骤图** | 步骤图是**逻辑顺序**（先做 A 再做 B），不要求真实时间戳。有真实时刻才算编年。 |

### A.4 常见数据缺陷与处置

| 缺陷 | 表现 | 处置 |
|---|---|---|
| 时间粒度不一致 | 有的精确到日，有的只知"1990 年代" | 用**模糊区间**符号（虚线段 / 渐隐端点），不可假装精确 |
| 时间戳缺失 | 只有先后无绝对时刻 | 降级为**序列轴（事件序轴）**，轴上刻度改为"第 1、2、3 事件"，并显式标注"顺序轴非等距时间轴" |
| 跨纪年断层 | 中间几十年无记录 | 显式**断轴符**（`//`），并注明压缩比例；禁止静默跳格 |
| 事件密度极端不均 | 某年 200 条、其余年份 3 条 | 主干轴保留等距时间，密度通过**次级条带 / 热力格**吸收，不做主轴缩放 |

## B 借用的统计图形与计算方式

编年型不自创图形，它**借用统计图形作为骨架，再用视觉编码改造为叙事载体**。这条"借用—改造"路径正是信息图形区别于数据可视化的关键。

### B.1 图形谱系（按 A.1 的四种形态对应）

| 数据形态 | 借用的统计图形 | 改造方向 |
|---|---|---|
| 定点事件 | 一维散点图（点图 / strip plot）、地毯图（rug plot） | 点→锚点符号；纵轴退化为**标签悬挂区**，用于错位排布文字 |
| 区间状态 | 甘特图（Gantt）、范围条（range bar）、水平条形图 | 条→泳道带；增加端点语义（开放端=持续至今） |
| 时间序列 | 折线图、面积图、阶梯图（step chart）、日历热力图 | 保留量的真实刻度，叠加事件锚点形成"趋势 + 事件"双读 |
| 纪元背景 | 分面（facet）、背景分段（band） | 面→时代色块，作为**底层语义分区**而非数据编码 |

### B.2 计算方式

编年型真正用到的"统计"很轻，但每一项都直接影响叙事：

1. **时间归一化**：把异构日期映射到统一刻度。三种映射会得到完全不同的图：
   - 线性时间（真实比例）——忠实，但早期事件会挤成一团；
   - 等距分类（每项等宽）——可读，但**夸大了晚期事件的密度**，必须标注；
   - 对数/开方时间——折中，适合跨度上万年的长史。
2. **事件密度**：`单位时间事件数 = count(t in bin) / bin_width`。用于决定次级条带、热力格的明度深浅。
3. **持续时长**：`duration = t_end − t_start`。条带长度即此值，必须与主轴共用同一时间刻度，否则长度失真。
4. **间隔（gap）**：相邻事件时间差。间隔大小是天然的叙事节奏器——大间隔=留白=时代转折。
5. **累计量**：`cumsum(value)`。用于"里程碑式增长"，配阶梯图。
6. **周期折叠**：把多年数据折叠到 12 个月 / 7 天的环形轴上，用于表现周期性（如季节性事件分布）。
7. **纪元压缩**：把 n 个节点归纳为 k 个纪元（`k ≪ n`），压缩比即叙事取舍强度。

### B.3 选择决策表

| 读者要回答的问题 | 选用 | 理由 |
|---|---|---|
| 一共发生了哪些大事？ | 单线直轴 + 定点事件 | 最省认知成本 |
| 两件事谁先谁后、重叠多久？ | 泳道并行 / 甘特 | 区间可比较 |
| 整体趋势如何、转折在哪一年？ | 折线 + 事件锚点 | 量值连续 |
| 事物如何一步步演化？ | 阶段式时间轴（分块 + 箭头） | 强调因果链 |
| 是否周而复始？ | 环形 / 螺旋时间轴 | 闭合表达循环 |
| 某事件引发多条支线？ | 分支时间轴（时间树） | 承认分叉 |

## C 视觉编码

视觉编码层是按 **点 → 线 → 面 → 体 → 符号 → 色彩 → 文字** 的顺序逐级施加的。顺序不可颠倒：先定骨架（线），再定节点（点），再定分区（面）。

### C.1 编码总表

| 视觉变量 | 在编年型中承担什么 | 可编码的数据维度 | 强度 |
|---|---|---|---|
| **线** | 时间主轴、泳道基线、事件引线 | 时间流向、类别归属、因果指向 | ★★★★★（骨架） |
| **点** | 事件锚点、节点圆 | 事件有无、类别、权重大小 | ★★★★★（内容） |
| **面** | 纪元色块、区间带、泳道底纹 | 时代分段、状态持续、并行线程 | ★★★★ |
| **体** | 透视深度、等距柱、立体节点 | 极少用；仅表达"层级嵌套的时间" | ★（慎用） |
| **符号** | ISO 图形、象形单位、箭头、断轴符 | 事件性质（战争/发明/发布）、量（象形重复） | ★★★★（识别） |
| **色彩** | 色相 / 明度 / 饱和度 / 透明度 | 类别、时代远近、重要性 | ★★★★（气氛+分组） |
| **文字** | 轴标签、事件标签、注释、导语 | 精确语义（唯一能承载因果解释的通道） | ★★★★★（意义） |

### C.2 逐项要点

**线（骨架）**
- 主轴粗细建议为事件引线粗细的 **2–3 倍**，建立"骨架—枝节"层级。
- 轴端点处理即语义：**开放箭头**=仍在延续；**实心端点**=已终止；**渐隐**=时间不可考。
- 断轴必须用专职符号（双斜线或波浪断口），且在图例中说明压缩比例。
- 垂直时间轴更利于标签排布（中英混排、长文本），水平时间轴更符合"进步"心理模型。**长文案优先垂直。**

**点（内容锚点）**
- 形状编码类别（圆=常规、方=制度/文件、三角=冲突、菱形=成果），**形状种类 ≤ 5**。
- 大小编码权重，用**面积**而非直径（`r ∝ √value`），并限制在 1 : 2.5 的直径比内，否则会撑破轴线。
- 空心态 vs 实心态：空心=存疑/推定日期，实心=确证。

**面（时代分区）**
- 纪元色块应使用**极低饱和度**（亮色主题下明度 ≥ 92%，暗色主题下与底色相差 ≤ 6%），仅作背景分区，绝不可压过事件。
- 相邻两个纪元色块之间要留**1–2px 的缝或有明度台阶**，否则边界会糊成一块。
- 区间带（甘特条）高度需与泳道间距协调，条高 : 间隙 ≈ 2 : 1 时最易扫读。

**体**
- 编年型几乎不需要立体。若必须用（如"历史地层"隐喻），只允许**单向等距投影**（一个方向 30°），且所有深度值必须对应真实层级，禁止为好看加厚度。

**符号**
- 优先使用**同一线宽的线性图标**（stroke 一致、圆角一致），与主轴形成笔触统一。
- 象形单位（pictogram / unit chart）：一个符号 = 一个固定基数，必须标"1 图标 = 1 万人"，且用**半个符号表示半单位**（截断而非缩放）。
- 箭头只用于表达"因果/进程方向"，不得用作纯装饰分隔。

**色彩**
- **色相**编码类别（行业、国家、人物线），最多 6 类，超出请改用符号或泳道。
- **明度/透明度**编码时间远近视距：越久远越浅（"时间褪色"），是编年型最有辨识度的编码习惯，但会与"重要性"冲突——**若二者冲突，让重要性优先，用符号加粗表达**。
- **饱和度**编码叙事权重：转折点用高饱和点缀色（通常 1 个，最多 2 个），其余走中性灰阶。
- 通篇点缀色（accent）**不超过 2 个色相**，这是信息图形与数据可视化的显著差异——前者靠克制建立叙事焦点。

**文字**
- 字号三级足矣：主标题 / 事件标题 / 注释。比值约 2 : 1.4 : 1。
- 轴刻度标签与事件标签必须使用**不同字重**区分层级，不可只靠字号。
- 标签排布采用**上下交错（staggered）**，单侧最多两行，第三行必须改用引线拉出。

### C.3 编码禁忌

- ❌ 用等距分类轴却标成连续年份（读者会误算真实间隔）
- ❌ 装饰性箭头、装饰性时间轴延伸线压过真实数据端点
- ❌ 事件点的直径编码量值（面积失真可达 2 倍以上）
- ❌ 同一张图混用两种时间方向（左→右 与 右→左）
- ❌ 纪元色块使用高饱和色，导致读者把背景读成数据

## D 数据／信息架构

### D.1 层结构（自下而上四层）

```
┌─ 叙事层   导语 / 主标题主张 / 结论标注
├─ 注释层   事件标签、引线、脚注、来源
├─ 事件层   点锚点、区间带、序列曲线
├─ 骨架层   时间主轴、刻度、纪元分区
└─ 底      背景色 / 网格（通常留白，不加网格）
```

四层严格遵守**自下而上的视觉重量递减**：骨架最重（线粗），事件次重（实心符号），注释再次（细字），叙事最轻（大字号但低密度）。

### D.2 四种架构模式

| 模式 | 结构 | 适用 | 容量上限 |
|---|---|---|---|
| **单线直轴** | 一条主轴，事件左右/上下交替悬挂 | 单对象大事记 | 15–20 个事件 |
| **双线对照** | 上下（或左右）两条平行轴 | 两对象对比（两国/两公司/生平对照） | 每侧 10–12 个 |
| **泳道并行** | 多条水平泳道共享同一时间刻度 | 多线程（多项目/多人物/多战场） | 5–7 条泳道 |
| **环形／螺旋** | 极坐标或螺旋路径 | 循环、周期性、长周期闭合叙事 | 12–24 个节点 |

### D.3 折叠策略（信息架构的核心动作）

编年型的架构难点永远是"事件太多"。三种折叠手法：

1. **分组折叠**：把同类事件合并为一个节点（"1990s 连续 8 次并购"），并在注释区展开明细。
2. **纪元折叠**：用纪元色块吸收"背景型事件"，只让"里程碑"占用主轴节点。压缩比建议 ≥ 3 : 1。
3. **主次分层**：主轴只放 3–5 个**必读锚点**，其余降级为次级条带的小点。**主轴节点数超过 7 个时，叙事即失效。**

### D.4 信息层级配额

一张编年型信息图的信息配额建议：

- 主轴必读节点：**3–5**
- 次级可读节点：**8–15**
- 背景纪元：**2–5**
- 文字总量：**80–250 字**（不含来源）
- 图例项：**≤ 5**

## E 视觉叙事架构

### E.1 阅读路径

| 轴向 | 路径 | 心理模型 |
|---|---|---|
| 水平 | 左 → 右 | 时间流逝 = 前进（拉丁/中文读者通用） |
| 垂直 | 上 → 下 | 编年史、地层堆积、下钻 |
| 环形 | 顺时针 | 循环、年轮、周期 |
| 蛇形 | Z 字折返 | 长内容压缩进方形版面 |

路径必须在第一眼可判读——**轴的起点要有明确视觉标记**（起点符号、起始年份加重、箭头）。

### E.2 五种叙事模式

| 模式 | 结构 | 情绪 | 典型场景 |
|---|---|---|---|
| **纪传式** | 单对象线性推进 | 沉稳、累积 | 企业史、人物生平 |
| **对位式** | 双轴平行，交错呼应 | 张力、比较 | 竞品史、双城记 |
| **兴衰式** | 高—低—高的曲线节奏 | 戏剧性 | 品牌沉浮、王朝更替 |
| **周期式** | 闭合环 | 恒常、秩序 | 节气、行业周期 |
| **分叉式** | 主干 + 分支树 | 抉择、可能性 | 技术路线演进、决策复盘 |

### E.3 叙事节奏（起·转·合）

编年型最忌"等权重平铺"，必须建立**重量差**：

- **起**：一个视觉重量正常的锚点，交代坐标系（时间范围、主体）。
- **转**：整张图的**唯一视觉高潮**——用高饱和点缀色 + 最大符号 + 最大留白包夹。转点前后各留 ≥ 1 个事件间距的空白。
- **合**：结尾以"开放端点 + 一句趋势判断"收束，不用感叹号，用事实。

> **节奏公式**：`留白 > 符号 > 色彩` 三条通道同时只允许一处高潮。三处都高潮等于没有高潮。

### E.4 图文分工

| 通道 | 只负责 | 禁止 |
|---|---|---|
| 主标题 | 一句**主张**（可被反驳的判断句） | 只写"XX 发展史"这类标签 |
| 副标题 | 时间范围 + 主体 + 数据口径 | 重复主标题 |
| 轴上标签 | 事实：时间 + 事件名（≤ 12 字） | 塞因果解释 |
| 注释/侧栏 | 因果、背景、数据出处 | 复述轴上已有事实 |
| 图例 | 编码规则 | 解释性长句 |

**一句话原则**：图上说"发生了什么"，文字说"为什么发生"。

## F 设计检查清单

制图完成后逐条自检（每条为二元判断）：

- [ ] 删掉时间轴后图形是否崩塌？（否则误用了编年型）
- [ ] 时间刻度类型（线性/等距/对数）是否已在图上标注？
- [ ] 点事件与区间状态是否用不同符号区分？
- [ ] 断轴、模糊日期是否都有显式符号？
- [ ] 主轴必读节点是否 ≤ 7？
- [ ] 是否存在且仅存在一个视觉高潮？
- [ ] 点缀色是否 ≤ 2 个色相？
- [ ] 事件标签是否 ≤ 12 字、层级 ≤ 3 级？
- [ ] 纪元色块是否明显弱于数据层？
- [ ] 主标题是否为可反驳的主张句？
- [ ] 数据来源与统计口径是否标注？
