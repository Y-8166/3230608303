## 0. 一句话定义

**层级型信息图形，是以"整体—部分"或"上级—下级"的包含／隶属关系为唯一组织骨架，通过嵌套空间（面积、缩进、连线、同心环）表达从属深度，从而回答"由什么构成、谁管谁、如何逐级分解"的信息图形。**

其本质是**把一棵树画成可读的空间**。读者要能在一眼之内回答三件事：谁是总、谁属于谁、每支占多少。

按类型学原理，层级型应为：

- **数据逻辑**：包含／隶属关系，可逐级分解，**存在唯一的根**——这是它与编年型的根本分野。层级关系**没有时间方向**，"单向、不可逆"描述的是时间轴，不是树。
- **视觉编码**：以**嵌套面积**（树图、旭日、圆堆积）或**连线位置**（组织图、缩进树）为主，而非"线性为主"。线在层级型中是父子关系的**附属表达**，不是骨架。

## A 基本的数据逻辑

### A.1 本质数据结构

层级型的本质是**树（Tree）**——一个有向无环、且**每个节点只有一个父节点**的图。标准节点记录：

```
(id, parent_id, name, value?, level?)
```

| 字段 | 语义 | 说明 |
|---|---|---|
| `id` / `parent_id` | 定义边，即包含关系 | 全表由此重建树；根节点 `parent_id = null` |
| `value` | 节点可测量的量（人数、金额、面积） | **决定面积/长度编码**，缺失则退化为结构图 |
| `level` | 深度层级（根=0） | 可由 `parent_id` 递归推导，作校验用 |

四种合法的层级形态：

| 形态 | 定义 | 图形化倾向 |
|---|---|---|
| **包含（Composition）** | A 由 B、C 组成，B+C+…=A | 面积类（树图、旭日、饼） |
| **隶属（Subordination）** | A 管辖 B、C，但 B+C ≠ A | 连线类（组织图、思维导图） |
| **分类（Classification）** | A 类下分 B、C 子类 | 缩进类（目录、分类树） |
| **分解（Decomposition）** | A 可拆为工序 B、C | 流程类（WBS、分解结构） |

> **重要区分**：只有"包含"关系满足**可加性**（子项之和 = 父项）。隶属与分类关系**不满足可加性**，因此绝不能用面积比例去编码它们——这是层级型最常见的错误。

### A.2 四问判定检验

1. **唯一父检验**：每个节点是否只隶属于一个上级？
   → 是：树，层级型成立。
   → 否（一个节点属于多个上级）：是**网络（Network）**，应改用和弦图/桑基图或力导向图，不属本门类。
2. **关系检验**：读者的问题是"由什么构成／谁归谁管"，还是"彼此有何关联"？
   → 前者=层级型；后者=关系型（网络）。
3. **可加性检验**：`Σ value(children) ≈ value(parent)` 是否成立？
   → 成立：可用面积/长度编码（比例型层级）。
   → 不成立：**只能画结构**，节点等大，另设标签标注数值（结构型层级）。
4. **深度检验**：最大深度 `max(level)` 是多少？
   → ≤ 3：可一张图读全（首选面积嵌套）。
   → ≥ 4：必须折叠，只展开 1–2 条关键路径（见 D.3）。

### A.3 与相邻门类的边界

| 易混对象 | 分界点 |
|---|---|
| **网络/关系图** | 有环、多父、无根 → 网络。层级型必有唯一根与唯一路径。 |
| **编目型** | 编目是并列集合，无父子。若清单可被严格分组且组内互斥，才升级为两级层级。 |
| **编年型** | 若"层级"实为"代际传承"（父公司→子公司→孙公司沿时间出现），主逻辑仍是层级，时间退为副键。 |
| **流程/步骤图** | 流程有前后依赖（A 完成后才能 B），层级是**同时并存**的包含。流程可视为"分解"的特殊形态。 |
| **饼图/环形图** | 饼图是层级型的**退化特例**（只有根 + 一层叶，深度=1）。深度 > 1 时饼图失效，须换旭日图。 |

### A.4 常见数据缺陷与处置

| 缺陷 | 处置 |
|---|---|
| 存在环（A 属 B，B 属 A） | 数据清洗阶段强制定向，人工判定真实父节点，禁止用"绘制时忽略环"蒙混 |
| 孤立节点（无 parent 且非根） | 归入"未分类"虚拟根，并在图例中显式说明 |
| 同级 value 量纲不一致（一个按人数、一个按金额） | 禁止同图混编面积；拆图或统一量纲 |
| value 缺失率高 | 放弃比例编码，转结构型（等大节点 + 数字标签） |
| 分支数 > 12 | 触发"其他"合并（Top-N + Others），并在注中标明合并基数 |

## B 借用的统计图形与计算方式

### B.1 图形谱系

层级型是统计图形家族里**最富有变体**的一支，因为它同时可借"面积""长度""位置""角度"四种通道：

| 借用图形 | 编码通道 | 可加性要求 | 深度上限 | 适用 |
|---|---|---|---|---|
| **矩形树图**（Treemap） | 面积 + 嵌套位置 | 必需 | 3–4 | 占比 + 层级同时看 |
| **旭日图**（Sunburst） | 角度 × 半径 | 必需 | 3 | 层级占比、环形叙事 |
| **圆堆积**（Circle Packing） | 面积 + 同心位置 | 必需 | 3 | 层级占位，弱化精确比较 |
| **冰柱图 / 树状图**（Icicle / Dendrogram） | 长度 + 缩进 | 可选 | 5+ | 分类学、聚类结构 |
| **组织架构图**（Org Chart） | 位置 + 连线 | 否 | 4 | 隶属、汇报线 |
| **缩进列表 / 目录树** | 缩进 + 序号 | 否 | 不限 | 分类、导航 |
| **金字塔 / 漏斗** | 宽度 | 部分 | 2–3 | 等级阶层、转化率 |
| **韦恩图**（Venn） | 交叠面积 | 否 | 2 | 集合交叠（严格说非层级） |
| **扇形分解图**（Exploded pie） | 角度 + 位移 | 必需 | 2 | 单一层拆分 |

### B.2 计算方式

1. **面积比例映射**：子节点面积 `A_i = A_parent × (v_i / Σv)`。这是树图/旭日/圆堆积的核心运算。
2. **矩形切分算法**：Squarified Treemap 使每个矩形的**长宽比趋近 1**（目标 ≤ 1.5）；Slice-and-Dice 会产出极端细长条，仅在需要"条带节奏"时使用。
3. **排序策略**：按值降序（默认，利于比较）/ 按语义顺序（如组织流程）/ 按时序。**排序不同，读者结论不同**，必须在注中说明排序依据。
4. **汇总（Roll-up）**：自叶向根累加，用于生成父级标签值。
5. **下钻（Drill-down）**：保留父级上下文的前提下展开某一支——通常实现为"局部放大 + 面包屑"。
6. **深度归一**：`opacity = 1 − 0.15 × level`，用透明度表达深度，替代多余的边框。
7. **分支宽度预算**：`max_children ≤ 7 ± 2`（米勒数），超出即触发合并。

### B.3 选择决策表

| 读者问题 | 选用 | 理由 |
|---|---|---|
| 各部分占比多少，且要看到子结构？ | 矩形树图 | 面积利用率最高，可容纳标签 |
| 占比 + 层级 + 环形美感？ | 旭日图 | 角度易读，外圈标签可斜排 |
| 只要结构，不比较大小？ | 组织图 / 缩进树 | 不受面积约束，文字可完整 |
| 层级很深，需要看路径？ | 冰柱图 | 长度代表深度，路径清晰 |
| 强调"层层收窄/转化"？ | 漏斗 / 金字塔 | 宽度即收窄，语义强 |
| 一定要用饼图？ | 仅当 ≤ 6 项且深度 = 1 | 超过即换树图 |

## C 视觉编码

### C.1 编码总表

| 视觉变量 | 在层级型中承担什么 | 可编码维度 | 强度 |
|---|---|---|---|
| **面** | 嵌套矩形、环形扇区、色块 | 占比（面积）、层级归属 | ★★★★★（主通道） |
| **位置** | 缩进、同心半径、上下层级 | 深度、兄弟顺序 | ★★★★★（结构） |
| **线** | 父子连线、缩进参考线、边框 | 隶属关系、层级分隔 | ★★★★ |
| **点** | 叶子节点符号、图标 | 节点类型 | ★★ |
| **符号** | 行业图标、叶节点象形 | 类别、可识别性 | ★★★ |
| **色彩** | 色相 = 顶层分支，明度 = 深度 | 分组、层级 | ★★★★（慎用于面积） |
| **体** | 3D 方块、等距柱 | 几乎不用 | ★（禁用） |
| **文字** | 节点名、数值、百分比 | 精确语义 | ★★★★★ |

### C.2 逐项要点

**面（主通道）**
- 树图的**矩形长宽比**是唯一硬指标：目标 ≤ 1.5，超过 3 即为失败（读者无法估面积）。
- 相邻矩形之间留 **2–4px 缝**（与画布同色的"呼吸缝"），比描边更干净；若必须描边，线宽 ≤ 1px 且为浅灰。
- 面积代表值，因此**标签必须放在面积最大的若干块内**；面积过小者改用**序号 + 外部图例**索引，禁止硬塞文字导致溢出。
- 旭日图扇区角度必须自 12 点方向顺时针起算，且各层**起始角对齐**（同一父级的子扇区共享起始角），否则无法追踪血缘。

**位置（结构）**
- 缩进量恒定，`indent = 16–24px/级`；缩进一旦不统一，层级读感立即崩坏。
- 组织图的**同层节点必须垂直对齐**（同一 y 坐标），这是组织图可读性的第一原则。
- 同心环半径建议 `r_n = r_0 × 1.35^n`，等比递增让外圈获得足够标签空间。

**线**
- 组织图连线用**肘形（elbow）直角折线**，不用斜线——斜线会让读者误判"路径长度=距离"。
- 连线粗细恒定，且**细于节点边框**，保证"节点是主体、线是附属"。
- 可选：连线中点加短竖线（"T 型"），表示"子女共同继承"，强化家族树语义。

**点 / 符号**
- 叶子节点若带图标，图标**只表类别，不表数量**；数量交给面积。
- 图标风格必须统一（同为线性或同为面性），线宽与文字笔画重量匹配。

**色彩**
- **色相编码顶层分支**（一级分类），子级只改明度/透明度，绝不换色相——这是层级型最重要的色彩纪律。
- 顶层分支 ≤ 6 个色相；每个色相准备 3–4 级明度台阶（对应深度 1/2/3）。
- 亮色主题：明度台阶建议 100% / 85% / 70% / 55%（相对同色相）；暗色主题反向。
- 严禁在树图里用"红绿"对立表大小（区域习惯冲突），大小交给面积。

**文字**
- 节点标签三级：分支名（粗，12–14pt）／节点名（常规，10–11pt）／数值（细，9–10pt，可降透明度）。
- 数值统一格式："占比 %"优先于绝对值（读者关心的是相对量）；若给绝对值，必须标单位与口径。
- 深度 ≥ 3 时，最内层标签允许省略，用悬停或图例补足（纸质则必须保留）。

### C.3 编码禁忌

- ❌ 用面积编码**不可加**的隶属关系（组织图里"部门人数"不能用方块面积表示而同时表示管辖）
- ❌ 树图矩形长宽比 > 3（无法估面积）
- ❌ 子级换色相（破坏"同族同色"的血缘读感）
- ❌ 3D 立体树图/立体饼图（透视使面积失真，前块视觉上大 30%+）
- ❌ 组织图同层不对齐
- ❌ 深度 > 3 仍强行全展开，导致标签全灭
- ❌ 用颜色深浅同时表达"深度"和"数值"（两个维度抢一个通道）

## D 数据／信息架构

### D.1 层结构

```
┌─ 叙事层   主标题（一句结构判断）/ 结论标注
├─ 注释层   节点名、数值、单位、图例
├─ 结构层   矩形/扇区/节点 + 父子连线
├─ 框架层   根容器、层级参考线、缩进基线
└─ 底      背景（纯色，不加网格）
```

### D.2 四种架构模式

| 模式 | 结构 | 适用 | 容量上限 |
|---|---|---|---|
| **嵌套面积** | 矩形递归切分 | 占比 + 层级 | 深度 3，叶 ≤ 40 |
| **同心分层** | 半径递增环 | 占比 + 环形语义 | 深度 3，叶 ≤ 30 |
| **缩进树** | 左对齐缩进 + 折线 | 分类、目录 | 深度不限，行 ≤ 30 |
| **连线图** | 中心辐射或自上而下 | 隶属、汇报 | 深度 4，节点 ≤ 25 |

### D.3 折叠策略

层级型的核心矛盾是"深度 × 宽度"的组合爆炸。三种处置：

1. **深度截断**：只画到第 3 层，第 3 层节点标"▸ 展开 12 项"。纸质媒体则改用"主图 + 局部放大框"。
2. **路径高亮**：全图只对 **1–2 条血缘路径**做完整着色，其余灰化（`opacity 0.25`）。这比全彩更能传达结构。
3. **Top-N + Others**：同级分支超过 7 个时，保留前 6 名 + "其他 (n)"，并在注中列明被合并项。

### D.4 信息层级配额

- 顶层分支：**3–6**
- 可见层级：**≤ 3**
- 可见叶节点：**≤ 40**（树图）/ **≤ 25**（组织图）
- 图例项：**≤ 6**
- 文字总量：**60–200 字**

## E 视觉叙事架构

### E.1 阅读路径

| 模式 | 路径 | 心理模型 |
|---|---|---|
| 树图 | 从左上大块 → 右下小块（Z 字） | 从主到次 |
| 旭日 | 圆心 → 外环（离心） | 从总到分 |
| 组织图 | 上 → 下 | 权力自上而下 |
| 缩进树 | 左 → 右 | 目录翻阅 |

**路径提示**：树图必须在视觉上让"根"可被立即识别——通常用最大面积 + 最深色 + 左上角定位三重手段共同实现。

### E.2 四种叙事模式

| 模式 | 结构 | 传达的判断 | 场景 |
|---|---|---|---|
| **演绎式** | 根 → 枝 → 叶 | "整体由这些构成" | 预算分解、人口构成 |
| **归纳式** | 叶 → 枝 → 根 | "这些零散项共同构成一件事" | 成本归集、证据汇总 |
| **聚焦式** | 全图灰化 + 单路径高亮 | "关键在于这一支" | 归因分析、组织变革 |
| **对照式** | 双树并列（同一结构两套数值） | "结构没变，量变了" | 同比、双公司对比 |

### E.3 叙事节奏

层级型没有时间，因此节奏靠**面积对比**与**色彩权重**建立：

- **起**：根节点/最大块 —— 视觉重量必须占全图 ≥ 25%，否则读者找不到入口。
- **转**：一处**预期违背**——某小块却颜色最深/带高亮标记，形成"次要但关键"的张力。全图仅允许一处。
- **合**：角落的汇总数字或一句结构判断（如"前 3 支占 78%"）。

> **比例即论点**：层级型把结论写进了面积。因此"选哪个维度做面积"就是"下什么结论"，必须在标题中把该判断说出来。

### E.4 图文分工

| 通道 | 只负责 | 禁止 |
|---|---|---|
| 主标题 | 结构判断句（"七成预算集中在两个部门"） | "组织架构图"这类标签 |
| 节点标签 | 名称 + 单一数值 | 名称 + 三个数值 + 说明 |
| 图例 | 色相→分支的对应 | 解释算法 |
| 注释 | 口径、排序依据、合并项 | 复述节点名 |

## F 设计检查清单

- [ ] 数据是否满足"唯一父"（否则应换网络图）？
- [ ] 面积编码的对象是否满足可加性？
- [ ] 树图最大长宽比是否 ≤ 1.5（极限 3）？
- [ ] 深度是否 ≤ 3（超出是否已折叠）？
- [ ] 同级分支是否 ≤ 7（超出是否已合并"其他"）？
- [ ] 子级是否只改明度、未换色相？
- [ ] 同层节点是否垂直对齐（组织图）？
- [ ] 缩进量是否恒定？
- [ ] 是否存在且仅存在一处视觉高潮？
- [ ] 主标题是否为结构判断句？
- [ ] 排序依据、合并项、口径是否标注？
