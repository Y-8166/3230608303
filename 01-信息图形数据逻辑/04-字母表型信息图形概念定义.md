## 0. 一句话定义

**字母表型信息图形，是以对象名称的字符序列（A→Z、拼音、笔画、假名行）为唯一排序依据，通过字母分区、首字母权重与索引条带建立可检索结构，从而回答"这个在哪、一共有多少、如何快速找到"的信息图形。**

它最反直觉的一点：**它的组织逻辑不来自内容，而来自符号系统本身**。这意味着读者不需要理解任何语义，仅凭"我知道它叫什么"就能定位——这正是它在信息量极大时不可替代的原因。

## A 基本的数据逻辑

### A.1 本质数据结构

字母表型的本质是**以名称为键的有序字典（Ordered Dictionary / Lexicon）**，排序函数是**字符序（Collation）**而非数值或时间。

```
entry[i] = { term, initial, sort_key, body?, meta? }
```

| 字段 | 语义 | 硬约束 |
|---|---|---|
| `term` | 条目名称（唯一入口） | 必备；必须**可被字符化** |
| `initial` | 首字母/首音节，决定分区 | 必备；由 `term` 派生，可预先计算 |
| `sort_key` | 排序键（可能长于 `initial`，含第二、三字母） | 必备；**中文需明确用拼音还是笔画** |
| `body` | 释义/正文 | 可选 |
| `meta` | 分类、来源、交叉引用 | 可选 |

四个必须预先决定的排序约定（不定则全篇失序）：

| 约定 | 选项 | 影响 |
|---|---|---|
| **字符集** | 拉丁 A–Z / 中文拼音 / 中文笔画 / 假名五十音 | 决定分区数量与视觉节奏 |
| **大小写** | 统一大写 / 保留原样 | 影响"看头"的整齐度 |
| **冠词处理** | "The Beatles" 归 T 还是 B | 影响检索直觉，须在图例说明 |
| **数字与非字母** | 数字条目置于前（0–9）或后（#） | 影响首尾分区 |

三种合法形态：

| 形态 | 结构 | 视觉产物 |
|---|---|---|
| **索引型**（Index） | 只有 `term` + 指向（页码/链接） | A–Z 索引条、目录 |
| **辞典型**（Lexicon） | `term` + `body` 短释义 | 词条页、术语表 |
| **图录型**（ABC Book） | `term` + 图形 + 一句说明 | A–Z 海报、字母卡片 |

### A.2 四问判定检验

1. **检索检验**：读者的入口是不是"**名称**"？（"我想找 X"）
   → 是：字母表型。
   → 否（入口是"哪年""哪类""哪里"）：归入 [编年](01-编年型信息图形概念定义.md) / [层级](02-层级型信息图形概念定义.md) / [地理](05-地理图形信息图形概念定义.md)。
2. **规模检验**：`n` 是否大到无法一屏扫读？
   → `n < 20`：不需要索引，直接编目（[03 编目型](03-编目型信息图形概念定义.md)）。
   → `n ≥ 20`：字母分区的收益开始超过成本。
   → `n ≥ 60`：字母表型几乎是唯一可行方案。
3. **无关系检验**：条目之间是否**缺乏**强时序、强层级、强关联？
   → 是：字母序是中性的"无观点排序"，不会误导。
   → 否：强用字母序会**掩盖真实结构**，此时应优先语义排序，字母索引退为附属导航。
4. **覆盖率检验**：26 个字母中实际有内容的字母占比多少？
   → < 40%：大量空区会让版面显得碎片化，改按"语义分组 + 组内字母序"。
   → ≥ 60%：纯 A–Z 分区成立。

### A.3 与相邻门类的边界

| 易混对象 | 分界点 |
|---|---|
| **编目型** | 编目按语义/大小排序，字段对齐；字母表按字符排序，条目长度可不等。二者常组合使用（"按品类分组，组内 A–Z"）。 |
| **层级型** | A→Z 分区只是**平级分区**，不是父子关系。切勿把"字母"画成树的一层（那会让人误以为有隶属语义）。 |
| **列表型** | 列表型用序号（1、2、3）排序，暗示"顺序有意义"；字母表型用字母排序，明确表示"顺序无意义，只为检索"。**这是二者的本质差异。** |
| **词云** | 词云按词频定字号、按算法散乱布局，**没有稳定检索路径**；字母表型恰恰相反，检索路径是它的全部价值。 |

### A.4 常见数据缺陷与处置

| 缺陷 | 处置 |
|---|---|
| 字母分布极不均（S 下有 30 条，X 下 0 条） | 保留空字母但压缩其占位（见 C.2 的"弹性分区"），不可删字母导致读者误以为漏页 |
| 中英混排 | 分两套索引（中文按拼音，英文按 A–Z），或统一转写并注明规则 |
| 名称有别名/俗称 | 主条目按正式名排序，别名在索引区做"见 XXX"交叉引用 |
| 同名字段（"苹果"既是水果又是公司） | 加限定词入 `sort_key`（"苹果（水果）"/"苹果（公司）"） |
| 条目长度差异百倍 | `body` 设行数上限，超出转"详见"链接 |

## B 借用的统计图形与计算方式

字母表型借用的统计图形几乎全部围绕**"分布"**——因为一旦要表达字母之外的信息，唯一自然的接口就是"每个字母下有多少东西"。

### B.1 图形谱系

| 借用图形 | 编码通道 | 用途 | 说明 |
|---|---|---|---|
| **首字母分布条形**（Index Density Bar） | 长度 | 各字母条目数 | 字母表型的"元图形"，可为索引区提供厚度变化 |
| **字母矩阵**（A–Z Grid） | 位置 + 面 | 字母覆盖率 | 26 格矩阵，有内容者填充，形成"字母地图" |
| **分区条带**（Section Band） | 位置 + 色相 | 分区导航 | A/B/C… 色带，贴在版边 |
| **词频/字频图** | 长度 | 术语热度 | 仅作辅助，需与字母序共存时慎用 |
| **面积/树图（按字母聚合）** | 面积 | 每字母的信息量占比 | 与 [层级型](02-层级型信息图形概念定义.md) 合流 |
| **散点（字母 × 属性）** | 位置 | 条目属性分布 | 用字母作分类轴，属性作纵轴 |

### B.2 计算方式

1. **首字母分组计数**：`count(initial = L)`，得到 26 个桶的频次。这是索引密度的唯一数据源。
2. **字符序比较（Collation）**：`compare(a, b)` 依 locale 规则。中文必须显式指定 `pinyin` 或 `stroke`，不同规则产出完全不同的顺序。
3. **弹性占位**：`height_L ∝ f(count_L)`，常用 `sqrt` 压缩，避免"S 区"吞掉半页。
4. **覆盖密度**：`coverage = 有内容字母数 / 26`，用于判定是否值得用纯 A–Z（见 A.2 第 4 问）。
5. **条目长度分布**：`len(body)` 的分布决定栏宽与行距（长条目需窄栏，短条目可宽栏）。
6. **交叉引用度**：`refs_in + refs_out`，用于识别"枢纽条目"，可加视觉权重。

### B.3 选择决策表

| 读者问题 | 选用 | 理由 |
|---|---|---|
| 我要找的那个词在哪？ | 纯 A–Z 分区条 | 最短检索路径 |
| 哪些字母内容最多？ | 首字母分布条形 + 分区 | 分布可见，仍可检索 |
| 术语量有多大、覆盖多广？ | 字母矩阵 | 一屏看尽覆盖 |
| 需要边查边读？ | 辞典型双栏 | 栏宽适配长文 |

## C 视觉编码

字母表型是**唯一把"字母本身当作图形元素"**的门类。因此它的视觉编码第一原则是：**字母必须被设计成结构符号，而不只是标签**。

### C.1 编码总表

| 视觉变量 | 在字母表型中承担什么 | 强度 |
|---|---|---|
| **文字（字母）** | 结构符号：分区标题、索引、首字下沉 | ★★★★★（灵魂） |
| **位置** | 分区序列、栏位、索引条位置 | ★★★★★（骨架） |
| **面** | 字母色块、分区底板、隔行底纹 | ★★★ |
| **线** | 分区基线、栏线、索引刻线 | ★★★ |
| **点** | 条目编号点、引用标记 | ★★ |
| **符号** | 字母作为图形（叠印、裁切、负空间） | ★★★★（识别） |
| **色彩** | 色相分区、明度表层级 | ★★★ |
| **体** | 极少（字母立体化仅作装饰，慎用） | ★ |

### C.2 逐项要点

**字母作为结构符号（本门类核心手法）**
- **尺寸阶梯**：分区字母（A、B、C）字号应为条目名的 **3–6 倍**，形成"墙上的门牌"效果；过小则失去导航功能。
- **字重与字色**：分区字母用最重字重，颜色可为中性灰（15–25% 黑）——**低对比的巨型字母**是最优雅的处理，因为它既提供结构又不抢内容。
- **首字下沉（Drop Cap）**：辞典型的经典手法，首字母占 2–3 行高，与正文形成"锚点"。
- **字母裁切/出血**：把巨型字母的一部分裁出画布边缘，制造"索引延伸出页面"的心理暗示，适合海报型。
- **字母叠印**：字母与图形叠印（正片叠底/负空间），把"检索符号"与"内容图像"合成一体，是字母表型最具图形感的手法。

**位置／分区**
- **弹性分区**：`分区高度 ∝ √(条目数)`。均匀分区是错的——会让 S 区拥挤、X 区空旷。
- **索引条**：垂直贴在版边，26 格（或有内容的 N 格），当前区高亮。索引条宽度 8–12px，是全图唯一可以"破格"的元素。
- **分区基线**：每个字母区顶部加一条横线，长度 = 内容宽度（非整版宽），形成"章节句读"。
- **栏数与栏宽**：辞典型双栏，单栏字符数 **45–75**（中文 20–35 字）；栏间距 ≥ 1.5 倍字高。

**面**
- 分区底板色块透明度 ≤ 6%，或改用**仅在索引条上着色**（更克制）。
- 隔行底纹仅用于条目密集区，透明度 ≤ 4%。

**线**
- 分区横线：1px，文字色 20%。
- **禁止竖栏线**：用栏间距替代，竖线会让辞典感变成表格感。

**符号**
- 条目若要配图标，图标应统一为线性且与字母同色系；图标**不得大于分区字母**，否则层级颠倒。
- 交叉引用标记（"→ 见 X"）用极小字号 + 箭头，不占独立行。

**色彩**
- 色相用于**分区组**（如 A–F 暖、G–M 中性、N–Z 冷），而非每个字母一色——26 色必然失控。
- 分区组数 ≤ 5。
- 若只做单色版（黑白印刷），靠**字重 + 尺寸 + 灰阶**建立层级，字母表型在单色下依然成立（这是它比色彩依赖型门类更稳健的地方）。

**文字**
- 条目名用 Medium，释义用 Regular，交叉引用用 Light + 60% 透明。
- 条目间距：同字母区内条目间距统一（`8–12px`），字母区之间间距为条目间距的 **2–3 倍**——靠间距而非线来分隔分区。
- 行距 `1.5–1.7` 倍字高（辞典型偏大，海报型可 1.3）。

### C.3 编码禁忌

- ❌ 分区字母均匀等高（忽略条目数量差异，导致分区失衡）
- ❌ 26 个字母各用一种颜色
- ❌ 字母字号与条目字号接近（失去导航功能）
- ❌ 用竖栏线分隔（辞典变表格）
- ❌ 删除空字母区（读者会以为遗漏）
- ❌ 把字母做成 3D 立体球（装饰压过内容，且降低可读性）
- ❌ 中文条目未声明拼音/笔画规则（顺序无法被验证）

## D 数据／信息架构

### D.1 层结构

```
┌─ 叙事层   主标题（覆盖范围与总量）/ 使用说明（排序规则）
├─ 检索层   A–Z 索引条、字母分区标题、交叉引用
├─ 条目层   term → body → meta
├─ 分区层   分区基线、间距节奏、栏位
└─ 框架层   网格、留白、页码
```

**注意层级倒置**：与编目型不同，字母表型的**检索层在条目层之上**（读者先定位字母，再读条目）。这是架构上的关键差异。

### D.2 四种架构模式

| 模式 | 结构 | 适用 | 容量 |
|---|---|---|---|
| **索引条式** | 版边垂直 A–Z + 主区条目 | 手册、年报附录 | 60–300 条 |
| **辞典双栏** | 双栏 + 首字下沉 + 分区线 | 术语表、词典 | 40–200 条 |
| **字母矩阵** | 6×5 或 5×5 字母格 | 海报、概览 | 26 格 |
| **字母卡片流** | 每个字母一张卡片，网格排布 | 社交图文、A–Z 系列 | 26 张 |

### D.3 折叠策略

1. **字母折叠**：`n > 120` 时，只展开高频字母区，低频区合并为"其他（Q, X, Y, Z…）"并标注。
2. **条目折叠**：每条正文限 60–120 字，超出转"详见"。
3. **层级折叠**：二级条目（如"苹果 → 品种"）用小字号缩进，不占分区。

### D.4 信息层级配额

- 分区数：**≤ 26**（有内容者），分区组 ≤ 5
- 单区条目：**3–30**（超过 30 建议在该字母下再做二级分区）
- 每条字数：**20–120**
- 索引条：**1 条**
- 文字总量：**300–1500 字**（字母表型是文字密度最高的门类）

## E 视觉叙事架构

### E.1 阅读路径

| 模式 | 路径 | 心理模型 |
|---|---|---|
| 索引式 | 索引条定位 → 跳至分区 → 逐条扫读 | 查字典 |
| 卡片流 | A→B→C 顺序翻页 | 集卡、连载 |
| 矩阵式 | 逐格扫视 | 概览全景 |

字母表型的阅读是**目标驱动的跳跃式阅读**，不是顺序阅读。因此它的核心体验指标是**"平均定位时间"**——索引条、分区字母、首字下沉这三件东西，全部是为缩短这个时间而存在的。

### E.2 四种叙事模式

| 模式 | 结构 | 传达的判断 | 场景 |
|---|---|---|---|
| **百科式** | 均质词条 + 完整覆盖 | "这是全貌，且无偏" | 术语表、年鉴 |
| **精选式**（A–Z 策展） | 每字母 1 条，强制均衡 | "我替你挑了 26 个" | 杂志专题、品牌内容 |
| **层级递进式** | 字母序 + 逐条加重 | "越往后越重要"（需极谨慎） | 教程、阶梯知识 |
| **游戏式** | 字母 + 图形强绑定 | "记住这个符号" | 儿童认知、品牌记忆 |

> **关于"层级递进式"的警告**：字母序本身是**无观点排序**。若你希望传达"后面比前面重要"，就破坏了字母表型的核心优势（中立性）。此时应改用编目+排序，而非字母序。

### E.3 叙事节奏

字母表型没有天然高潮，节奏来自**分区的疏密交替**：

- **起**：索引条 + 第一个高密度分区，建立"这里内容很多"的预期。
- **转**：在**低密度区**（如只有 1–2 条的 J、K）插入一条特别的条目（最长正文/唯一配图/唯一高亮）。疏密对比本身就是节奏。
- **合**：末区（Z）常配一个"总结条目"或视觉收尾，避免图在角落草草结束。

> **疏密即节奏**：不要为了"填满"而删除空字母——**空区是呼吸，是节奏的一部分**。

### E.4 图文分工

| 通道 | 只负责 | 禁止 |
|---|---|---|
| 主标题 | 覆盖范围 + 总量（"126 个术语，从 A 到 Z"） | "术语表" |
| 使用说明 | 排序规则、别名规则 | 长篇导言 |
| 分区字母 | 导航 | 附加释义 |
| 条目正文 | 定义/说明（一句一事） | 多段论证 |
| 交叉引用 | "见 X" | 说明理由 |

## F 设计检查清单

- [ ] 读者入口是否真的是"名称"？
- [ ] 条目数是否 ≥ 20（否则不必用字母分区）？
- [ ] 排序规则（拼音/笔画/大小写/冠词/数字）是否已声明？
- [ ] 分区高度是否按条目数弹性分配（非均匀）？
- [ ] 空字母区是否保留并压缩（未删除）？
- [ ] 分区字母字号是否为条目名的 3 倍以上？
- [ ] 是否用间距而非竖线分隔分区？
- [ ] 索引条是否存在且可用？
- [ ] 分区组色相是否 ≤ 5？
- [ ] 是否有交叉引用处理别名？
- [ ] 单栏字符数是否在 45–75（中文 20–35）之间？
- [ ] 主标题是否给出覆盖范围与总量？
