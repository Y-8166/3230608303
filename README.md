# 信息图形研究库（xinxitubiao）

以**数据逻辑**为分类轴，系统整理信息图形（Information Graphics）的类型定义、视觉编码方法、案例库与制作方法论。

本仓库解决一个具体问题：**拿到一批数据，该画成什么？** 不是"有哪些图表"，而是"这份数据的结构本身，决定了它只能被画成哪一种图"。

> **主要源出**：《第三讲·信息图形类型学》（Information Graphics Typology），共 73 页，含第 3 章类型学、第 4 章艺术与交流、第 5 章表达与挖掘。本库对原讲义进行了**补充、修改与核实**，凡与讲义不一致处均在下文「八、与讲义的核实记录」中逐条说明。

**三层分工**（这是本仓库的核心设计）：

| 层 | 存放 | 内容 | 不含 |
|---|---|---|---|
| `01-` 理论层 | 5 份门类定义 | A 数据逻辑 / B 统计图形 / C 视觉编码 / D 信息架构 / E 视觉叙事 | **不含任何图片**，全部经文本链接指向 02 |

**链接方向**：`01 → 02`（理论指向实例），单向。02 可以回指 01 做映射，但 01 内**永不嵌图**——这样理论文档可以在任何纯文本环境（GitHub 裸页、终端、Word 导入）中完整阅读。

**为什么分三层**：第三讲的结构本身就是三层——先讲**类型**（是什么），再讲**形式**（长什么样），最后讲**方法**（怎么做好）。本库与之对齐，避免把"定义""案例""方法"混在同一份文档里互相稀释。

## 二、五类数据逻辑总览

这是本仓库的**总索引**。研判一份数据属哪一类，先看这张表。

| 门类 | 组织骨架 | 本质数据结构 | 回答的问题 | 判定要点 | 文档 |
|---|---|---|---|---|---|
| **编年型** | 时间轴 | `(t, entity, payload, span?)` 有序序列 | 何时发生？先后如何？ | 删掉时间，图形是否崩塌 | [01](01-信息图形数据逻辑/01-编年型信息图形概念定义.md) |
| **层级型** | 包含/隶属 | 树：`(id, parent_id, value)` | 由什么构成？谁管谁？ | 每个节点是否只有一个父 | [02](01-信息图形数据逻辑/02-层级型信息图形概念定义.md) |
| **编目型** | 字段对齐的并列网格 | 实体—属性矩阵 | 有哪些？差在哪？ | 能否抽出同一套字段 | [03](01-信息图形数据逻辑/03-编目型信息图形概念定义.md) |
| **字母表型** | 字符序 | 有序字典（以名称为键） | 这个在哪？ | 读者入口是否为"名称" | [04](01-信息图形数据逻辑/04-字母表型信息图形概念定义.md) |
| **地理图形** | 空间坐标 | 几何 + 属性（点线面流场） | 在哪？为何在此？ | 位置本身是否有解释力 | [05](01-信息图形数据逻辑/05-地理图形信息图形概念定义.md) |

### 2.1 三组必须分清的分界

1. **编目 vs 字母表**：按语义排序 = 编目；按字符排序 = 字母表。**前者表达观点，后者提供检索。**
2. **编目 vs 层级**：并列 = 编目；可加（子项之和 = 父项）= 层级。不可加的关系**绝不能用面积编码**。
3. **地理 vs 编年**：主轴是空间还是时间。二者叠合（行军、迁徙）= **混合型**。

### 2.2 混合型的位置

混合型**不属于五类基础逻辑**，而是其中 ≥ 2 类的叠合形态。它与"数据可视化"的分野：
> 数据可视化把数据**画准**；混合型信息图形把数据**画成论点**。

详见 [混合型案例](02-信息图形类型案例/01-混合型信息图形案例.md#0-类型定位混合型为什么不是第六类)。

### 2.3 逻辑层与形式层：两套坐标

以上五类属**逻辑层**（由数据结构决定，不可自由选择）。讲义 3-6 节另列**十七种常用形式**（混合型、时间轴型、示意图型、比较型、地标型、图片式、单一图表型、视觉简历、解剖型……），属**形式层**（可自由选择，同一逻辑可长出多种形式）。

制图时的正确顺序是**先定逻辑、再选形式**，反过来就会造出不存在的先后关系。完整对照表与四类边界说明见 [02-类型总览](02-信息图形类型案例/00-类型总览.md)。

## 三、更新原则

本库随案例增长**持续改写**，而非一次成稿。五条原则：

### P1 案例优先于理论
任何一条规则必须有**案例依据**（规则表须标注依据的 CASE 编号）。无依据的条目要么标"待验证"，要么删除。**禁止凭印象写规则。**

### P2 冲突时以案例为准
当既有理论与新案例冲突时，**改写理论**，不改写案例描述。案例是事实，理论是解释。

### P3 增量而非重写
新案例只能**追加**到登记表与分析区；已归档的案例解析不得被覆盖（可补充"后续观察"）。归纳区（规则表）则允许改写——它是活文档。

### P4 一条规则一个判据
规则必须写成**可执行、可检验**的形式：含具体数值、阈值或二元判断。禁止"注意留白""保持简洁"这类无法验证的表述。

### P5 反向记录失败
每个案例必须记录"⑦ 问题与风险"。**优秀案例的可复用要点，往往不如它的缺陷更有教学价值。**

## 四、案例登记规范

### 4.1 编号规则

```
CASE-<类型码>-<三位序号>

类型码：M = Mixed Charts（混合型）
        L = List / Informational（文字型·列表型）
        T = Timeline（时间轴型）

例：CASE-M-001、CASE-T-014
```

序号**只增不减**，删除案例时编号作废不复用（保留空行并标注"已废弃"）。

### 4.2 图版命名

```
assets/<类型码小写>-<三位序号>.<扩展名>

例：assets/m-001.jpg
    assets/t-014.png
```

要求：
- 长边 ≥ 1600px，JPEG 质量 ≥ 85（保证可放大看细节）
- 文件名全小写、无空格、不用中文
- 一图一档；系列图用 `-a`/`-b` 后缀（`t-014-a.jpg`）

### 4.3 必填字段

每个案例必须填齐 7 栏（模板见各案例文档第 4/5 节）：

| 栏 | 要求 |
|---|---|
| ① 数据逻辑拆解 | 主逻辑 + 辅逻辑，须能对应到 `01-` 中的门类 |
| ② 统计图形/刻度 | 必须指出借用了哪种统计图形、刻度是否等比 |
| ③ 视觉编码 | 点线面体符号色彩文字，逐项写 |
| ④ 数据/信息架构 | 层数、锚位置、折叠手法、信息配额 |
| ⑤ 视觉叙事架构 | 阅读路径、叙事模式、起转合、唯一高潮 |
| ⑥ 可复用要点 | ≤ 3 条，必须是操作规则 |
| ⑦ 问题与风险 | 至少 1 条，不得写"无" |

### 4.4 归档流程（SOP）

```
① 收图   → 存入 assets/，按 4.2 命名
② 拆解   → 复制模板，逐栏填写（7 栏缺一不可）
③ 登表   → 在"案例登记表"追加一行，状态改为 ✅ 已归档
④ 归纳   → 检查规则表：是否有新规则？是否有旧规则被推翻？
⑤ 回链   → 若该案例能印证 01 中某门类，在该门类 G 节追加链接
⑥ 记日志 → 在对应文档"更新日志"追加一行（日期 + 变更摘要）
```

第 ④ 步是**唯一不可省略**的一步——只归档不归纳，本库就退化为图片收藏夹。

## 五、文档写作约定

1. **每份门类文档固定五段**：A 基本数据逻辑 / B 统计图形与计算 / C 视觉编码 / D 数据信息架构 / E 视觉叙事架构。顺序不得调整，便于横向对照。
2. **所有判据必须可执行**：给数值、给阈值、给二元检验。例："树图矩形长宽比 ≤ 1.5"优于"保持矩形匀称"。
3. **禁忌用 ❌ 列表**：每份文档的 C 节须有"编码禁忌"，这是最高效的知识形态。
4. **检查清单用复选框**：每份文档末尾须有 F 节自检清单，条目为二元判断。
5. **不含图片（01 层）**；02 层图片一律走 `assets/` 相对路径。
6. **中文优先**，专业术语首次出现附英文原名。

## 七、合规提示（地理图形相关）

地理图形是唯一受法律强制约束的信息图形门类。制图前必读 [05 文档 F 节](01-信息图形数据逻辑/05-地理图形信息图形概念定义.md#f-合规与制图纪律中国地图强制项)，要点：

- 底图仅可用腾讯地图 / 高德 / 百度 / 天地图；禁用境外未备案地图源
- 中国全图必须完整表示台湾岛、海南岛、南海诸岛等法定要素，并附南海诸岛附图
- 国界线以自然资源部标准地图为准；公开使用须标注审图号
- 面数据必须归一化；分级方法必须声明
