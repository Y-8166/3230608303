# 规则 7 ｜ 图底关系 Figure–Ground

> **一句话**：先分出"什么是图、什么是底"，才谈得上分组。
> **证据等级**：原始文献（Rubin 1915，被格式塔吸收）｜C 节参数为经验值
> **位置**：本层 11 条主规则之 7 ｜ 总览：[00-总览与索引](00-总览与索引.md)
> **上一篇**：[良好图形／简洁律](06-良好图形-Pragnanz.md) ｜ **下一篇**：[共同区域](08-共同区域-Common-Region.md)

## A 定义

知觉把视野切成两部分：**图（figure）**——有形状、在前、承载对象；**底（ground）**——无形状、在后、延展无界。Rubin 1915 用杯／人脸双关图证明这条边界可以反转。

**可操作版**：信息图形里必须明确"数据是图、装饰是底"。任何与数据争夺"图"的地位的元素（高饱和照片、重纹理底图、水印），都会让读者把装饰读成数据。

**边界**：它管**分离**，不管分组。这是它与其他十条性质不同的地方——它是前置条件。

## B 知觉机制

图底分离依赖一组线索：明度对比、清晰度、包围关系（被包围的更像图）、大小（小的更像图）、运动（动的更像图）、对称性（对称的更像图）。信息图形主要用前三条。

## C 编码手段

| 线索 | 做法 | 参数（经验值，待验证） |
|---|---|---|
| 明度对比 | 图与底的明度差要足够；数据层永远比装饰层对比高 | 数据 : 底 ≥ 3 : 1（对比度） |
| 虚实 | 底图降饱和／降对比；可加蒙版 | 底图降饱和 30–50%，或覆 10–20% 白／黑蒙版 |
| 清晰度 | 底图可轻微模糊（不是滤镜炫技，是拉开层次） | 模糊半径 ≥ 1 px |
| 包围 | 数据被包围 → 更像图；底图不要包住数据 | — |
| 边界 | 图有边、底无边；底图不加框 | — |
| 留白 | 留白属于"底"，用来托图，不要填满 | 图周围留白 ≥ 1× 图元尺寸 |

## D 案例

**正例 1｜[CASE-0006 城市空间规划图](../02-信息图形类型案例/案例记录/CASE-0006-城市空间规划图.md)**（p.17）
可见事实：圆形城区道路与空间分区为主。本库判读：路网是**底**（细线、低对比、连续不断），分区色块是**图**（面、较高饱和、有边界）。读者先看到"几块功能区"，再顺着路网定位——层次正确。

**正例 2｜[CASE-0014 摄影嵌入图表](../02-信息图形类型案例/案例记录/CASE-0014-摄影嵌入图表.md)**（p.29）
可见事实：柱形统计叠加新闻照片与高亮色，照片承担语境而非量尺。本库判读：照片被压到"底"（降饱和／暗化／局部裁切），柱形与高亮色留在"图"层——这样照片提供情绪，不干扰读数。这是图文混合图唯一正确的层级安排。

**反例｜同一类图里让照片抢成"图"**
当新闻照片保持全彩高对比，且强调色与照片主色相近时，读者的第一注视点会落在人脸而不是数据上，柱形退为背景。错在**没有拉开图底对比**：照片既占据大面积、又保持高饱和，按 Rubin 的线索（大小 + 对比）它必然成为"图"。补救：降饱和 + 暗化 + 缩小，或裁掉人脸区域。

## E 设计实践经验

- **可逆的图底在信息图形里是错误，不是趣味。** 杯／脸双关适合海报，不适合读数——读者一旦在图底之间摇摆，就无法稳定读数。
- **水印必须真的像"底"。** 半透明 logo 压在数据上，会被读成叠加的编码（尤其当它是彩色时）。
- **深色底的图要额外检查。** 深底 + 亮数据时，读者容易把亮色块看作"发光物体"（图），把暗色数据看作"阴影"（底）；对比关系要拉得更开。
- **照片永远是底。** 只要照片参与"读数"，就是错的——照片只能承担语境、情绪、指认。

## F 自检清单

- [ ] 遮住所有装饰（底图、纹理、照片），数据是否仍然完整可读？
- [ ] 数据层与底层的对比度是否 ≥ 3:1？
- [ ] 有没有元素在图底之间摇摆（看久了会翻转）？
- [ ] 水印／logo 是否落在"底"的位置，且不承载信息？
- [ ] 照片是否只承担语境，没有参与量尺？
- [ ] 底图是否被加了不该有的边框（会让它变成"图"）？
