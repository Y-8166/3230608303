## 1. 四步设计流程（p.43）

课程给出一条极简的四阶段流程，值得逐字保留：

```
A  数据收集与数据清洗
B  数据集与结构搭建
C  视觉编码与版式排布
D  数据关联与内容呈现
```

### A 数据收集与数据清洗

| 要做 | 检验 |
|---|---|
| 确认口径（时间范围、单位、总体） | 同一指标三个来源是否一致 |
| 处理缺失、异常、重复 | 缺失是否显式标为"无数据"而非留白 |
| 统一量纲与精度 | 有效位数是否统一到最粗项 |

> **本库补充**：地理类数据必须在此阶段完成坐标系统一（GCJ-02 / CGCS2000）与归一化，否则到 C 步无法挽回。见 [地理图形 F 节](../01-信息图形数据逻辑/05-地理图形信息图形概念定义.md)。

### B 数据集与结构搭建

这是**四步中最关键、也最容易被跳过**的一步：把清洗后的表，转化为**符合某种数据逻辑的结构**（树 / 时序 / 矩阵 / 索引 / 空间）。

判断依据即 [五类数据逻辑](../01-信息图形数据逻辑/) 的四问判定。**此步未完成就进入 C 步，必然产出"形式先于内容"的图。**

### C 视觉编码与版式排布

按 **点 → 线 → 面 → 体 → 符号 → 色彩 → 文字** 的顺序逐级施加（顺序不可颠倒：先定骨架，再定节点，再定分区）。各门类的具体规则见 01 文件夹 C 节。

### D 数据关联与内容呈现

处理"图与图之间、图与文字之间"的关系：标题主张、注释、图例、来源、多图并置与联动。

> **常见误区**：把 D 当成"加个标题"。实际上 D 决定读者能否把图形转成**结论**——没有 D，前三个阶段的产出只是"画好了的图"，不是"信息图形"。

## 2. 初学者的四大硬伤（p.44）

课程把最常见的失败归为四类，并各给一句诊断：

| # | 硬伤 | 课程诊断语 | 真正的病因 | 对应修复 |
|---|---|---|---|---|
| 1 | **太复杂** | 数据没看懂 | 数据未清洗／口径混乱 | 回到 A 步 |
| 2 | **太抽象** | 看懂了，没考虑读者 | 形式与读者不匹配 | [选题原则 II](01-选题原则.md#原则-ii形式运作机制与读者背景知识的匹配性) |
| 3 | **无美感** | 看 Excel 看多了 | 缺视觉层级与留白纪律 | 见 [03](03-简洁与数据油墨比.md) |
| 4 | **内容多** | 数据整合没做好 | 未折叠（什么都想放） | 折叠策略（各门类 D.3） |

### 2.1 四伤的排序意义

注意课程给出的**诊断语结构**：三条都以"看懂了"或"看不懂"开头——说明**读者的理解状态是第一诊断量**，而不是美观度。

本库据此给出诊断顺序：

```
读者看不懂 ──→ ① 太复杂（数据问题）
    │
    └─ 看懂了但没感觉 ──→ ② 太抽象（读者问题）
                        └─ 有感觉但不美 ──→ ③ 无美感（执行问题）
                                          └─ 美但读不完 ──→ ④ 内容多（取舍问题）
```

**四伤是递进的**：前一个未解决，后一个无法诊断。因此修图必须按 ①→②→③→④ 的顺序，不能跳级美化。

## 3. 可视化轮盘：六组对立轴（p.45、p.48–53、p.69）

课程提出的核心调和工具。它不是"选边站"，而是把六组张力变成**可调的连续参数**——每张图在每条轴上都有一个位置。

### 3.1 六轴定义

| # | 轴左端 | 轴右端 | 变量本质 | 何时偏左 | 何时偏右 |
|---|---|---|---|---|---|
| 1 | **抽象**（概念化） | **模拟**（具象） | 图形是否描绘实物 | 数据关系抽象、读者专业 | 面向大众、需记忆点 |
| 2 | **实用**（朴素） | **修饰**（花哨） | 装饰的量 | 报告、仪表盘、印刷 | 海报、社媒、展陈 |
| 3 | **致密** | **稀疏** | 单位面积的信息量 | 专业读者、深度分析 | 大众媒体、快速传达 |
| 4 | **多维** | **单维** | 同时编码的变量数 | 探索型阅读、可交互 | 单一论点、静态印刷 |
| 5 | **创新**（独特性） | **通用**（普遍性） | 形式的新颖度 | 品牌表达、记忆点 | 通用报表、降低学习成本 |
| 6 | **简洁**（清晰） | **冗余**（深度） | 是否保留重复与多层信息 | 单一结论 | 需要自证、需要多路径阅读 |

> **关于第 6 轴的特别说明**：课程把"冗余"与"深度"并列，是有意的——**冗余不等于废话**。图表中的冗余指同一信息以多种方式重复呈现（如同时给数值标签与条形长度、同时给图例与直接标注），它增加了**容错性**与**可挖掘性**，代价是版面与注意力。这与 Tufte 的"数据油墨比"形成真实张力，见 [03](03-简洁与数据油墨比.md#3-与可视化轮盘的张力)。

### 3.2 轮盘的正确用法

**不是**把六轴都调到中点，而是**按选题定位置**：

```
① 定读者（专业/大众）        → 决定轴 1、3 的区间
② 定载体（印刷/屏幕/展陈）     → 决定轴 4（能否交互）、轴 5（新颖度预算）
③ 定论点数量（1 个 / 多个）    → 决定轴 6
④ 定品牌约束                 → 决定轴 2
```

**关键纪律**：六轴的取值必须在**动笔前**确定，并在全图内保持一致。中途改轴＝重画。

### 3.3 三处最常犯的错配

| 错配 | 表现 | 后果 |
|---|---|---|
| 要"通用"却做了"创新" | 用罕见图形做常规报表 | 读者学习成本高于收益 |
| 要"简洁"却要"多维" | 一张图塞 5 个变量 | 编码冲突，读者放弃 |
| 要"模拟"却数据抽象 | 用插画解释统计关系 | 插画承载不了关系，沦为装饰 |

## 4. 用轮盘做分层组织（p.69）

课程把轮盘落到具体版面结构上，给出三层法：

> 1. 按层次组织你的图表。提供数据概要，以主要数据集作为图表的切入点，引导读者阅读后续内容。
> 2. 第二层，应该尽可能多地包含内部信息。
> 3. 用逻辑顺序构建层级关系。编辑导航信息让读者可以根据自己的意愿发掘信息。

### 4.1 三层的映射

| 层 | 职能 | 对应轴取值 | 本库对应概念 |
|---|---|---|---|
| **第一层（概要）** | 一个主张 + 一组核心数字 | 偏"稀疏""单维""简洁" | 主轴必读节点 ≤ 7 |
| **第二层（内部信息）** | 尽可能多的细节，供深挖 | 偏"致密""多维""冗余" | 次级节点、注释、侧栏 |
| **第三层（导航）** | 逻辑顺序 + 跳转线索 | 偏"通用" | 编号、图例、交叉引用 |

### 4.2 为什么"第二层要尽可能多"

这一条与"简洁"看似矛盾，实则是**分层的结果**：第一层已经保证了快速读懂，因此第二层可以放心堆信息——**冗余被隔离在深层，不污染入口**。

这正是 [混合型 CASE-M-002](../02-信息图形类型案例/01-混合型信息图形-Mixed-Charts.md) 用编号把 150+ 条任务外挂到侧栏的原理：**入口极简，深层极密。**

## 5. 四条铁律（p.70）

课程在 5-4 节末尾给出的四句，可作为全流程的最终裁决：

| # | 铁律 | 违反后的典型症状 |
|---|---|---|
| 1 | **首先考虑（数据）结构，然后才是修饰的成分。** | 图形漂亮但读不出关系 |
| 2 | **检验修饰的成分是否大于实质内容。** | 遮掩数据：装饰抢走注意力 |
| 3 | **不要在确定数据的组织方式或排列结构之前考虑形式风格因素。** | 先定"我要做时间轴"，再硬塞数据 |
| 4 | **绝对不要因为你认为读者不能"理解"而简化数据。** | 删掉了关键变量，图变得"易懂但错" |

> 第 4 条与 [选题原则 III](01-选题原则.md#原则-iii专业度随读者专业度递进) 呼应，但更进一步：**"读者看不懂"不是删数据的理由，而是换形式的理由**。
> 换言之——降低**形式**的难度可以，降低**数据**的完整度不可以。这个区分是整讲的伦理底线。

## 6. 全流程自检清单

### 阶段 A
- [ ] 口径（范围/单位/总体）是否写明？
- [ ] 缺失值是否显式标注？
- [ ] 地理数据坐标系是否统一？

### 阶段 B
- [ ] 数据属于哪一类逻辑？四问是否通过？
- [ ] 是否需要在两类逻辑间取舍？取舍理由是什么？

### 阶段 C
- [ ] 编码是否按 点→线→面→符号→色彩→文字 的顺序施加？
- [ ] 是否只有一个视觉锚？
- [ ] 每个视觉通道是否只编码一个维度？

### 阶段 D
- [ ] 标题是否为可被反驳的主张？
- [ ] 是否存在且仅存在一处视觉高潮？
- [ ] 图例、来源、口径是否齐备？

### 轮盘
- [ ] 六轴取值是否在动笔前确定？
- [ ] 全图内六轴取值是否一致？
- [ ] 是否存在"要通用却做创新"这类错配？

### 四伤
- [ ] 是否按 ①→②→③→④ 的顺序诊断，而非直接美化？
- [ ] 若"内容多"，是否执行了折叠而非删数据？
